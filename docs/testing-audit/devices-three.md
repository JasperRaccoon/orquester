All 16 test files from remote `610d3c53` were read beside their production owners. ## Independent contract sources

- Phase 1 core spec §10.1 requires normalized begin/move/end input with letterbox and rotation mapping, and an agent tap overlay; §10.4 requires shipping GLBs and real meshopt loading.
- Phase 3 research spec §2.2 requires the added Apple/Samsung models, exact AVD mapping, normalized display/hinge rigs and reported fold posture.
- `scripts/convert-device-model.py` defines serialized model format: centred 2.2-unit display facing +Z, required fold halves and display names. These format assertions remain; body aspect, spine offsets and cosmetic resting poses do not.
- `three/README.md` documents caller interfaces (onTouch, projectPoint, notifyFrame, native framebuffer orientation, fallback, fold/accessory ownership). It does not establish a requirement for incidental scene structure, CSS geometry or arbitrary motion sensitivity.

## Six-bar evidence

Each survivor row in the companion JSON contains its individual B1–B6 evidence, unique failure, stable seam and production callers. The following common oracle rules apply: fixed normalized wire coordinates are independent from projection code; Three camera projection of a real framebuffer mesh is independent from screenPoint/viewPoint; controlled asynchronous completion proves ownership and selected-source outcomes; actual shipped GLBs exercise production loader configuration and format validation. No geometry snapshot or markup/source inspection survives. Retired CONSOLIDATE rows use their surviving owner’s six-bar evidence.
