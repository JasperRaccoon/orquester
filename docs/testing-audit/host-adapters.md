# Codex, Grok and common adapter test audit

Scope: **49 baseline files / 752 test declarations or parameterized families / 20,144 test LOC**. Claude and OpenCode are recorded separately. Every declaration below inherits its file-specific contract record. Assertion excerpts are frozen-baseline evidence; REWRITE/CONSOLIDATE rows describe the surviving oracles. Generated provider bindings and captured bytes are unchanged.

Declaration dispositions: {'KEEP': 736, 'REWRITE': 8, 'CONSOLIDATE': 3, 'OPTIMIZE': 5}. CONSOLIDATE has two surviving owners and one removed scenario; no unique workflow was deleted. Runtime expanded test counts differ from declaration/family counts.

## Six behavioral requirements

1. Each file record identifies an independent design/protocol/security source. A test title below identifies the exact scenario and failure within that contract; pure units are retained only for the listed credible failures.
2. The observed wrong wire value, lost/duplicated row, changed session state, incorrect persisted data, exposed credential or process effect is caller-visible. The individual scenario distinguishes its failure from neighboring cases.
3. Oracles are literal protocol fields, captured provider text/numbers, independent elapsed windows, fixture-controlled identity/order or actual OS effects. Provider mocks emit raw inputs and record outputs; they do not compute normalized behavior. Fixture self-checks and the injected cache-capacity oracle are removed.
4. The seam column below names the production-used boundary. Child-process tests retain real framing/spawn; real fold/liveness is used only where its cross-boundary interpretation is the contract.
5. Retained assertions concern returned values/events/wire bytes or OS effects; equivalent parser, collection or class refactors can preserve these. Removed assertions pinned helper RPC inventories, Object.keys inventory, incidental error prose or fixture declarations. The captured wire formats themselves are compatibility contracts.
6. Each file record explains why neighboring lower/higher tests do not supersede its protection. Mapping/state tables stay in their cheapest owner; actual session tests retain distinct lifecycle wiring and races. The specific test title records the unique input/state/order distinction. Duplicate model-context startup was merged into its two-turn owner; no-context omission moved into an already-running lifecycle scenario.

## Implemented decisions

- Grok replay keeps captured frames/order and outbound request/reply barriers. Per-frame 1–25ms sleeps become I/O yields. All six session workflows retain their meaningful assertions. Fixture20 replaces an incidental count of three turn-end liveness samples with monitor-specific liveness throughout its complete task lifecycle. Baseline leaf durations totaled15,432.6ms; fixture16 alone imposed3,927ms artificial delays and took4,132.2ms. Comparable final timings and mutation checks are recorded below.
- Codex model-context tests share one two-turn session: app data remains untrusted, changes are read on the next turn, and toolkit instructions stay application context. The no-app/no-toolkit field omission assertion is retained in the existing two-turn session test.
- The MCP capture fallback uses the real documented15s deadline under native timers, including a14999ms non-expiry check. The listing cache uses the documented30s TTL and immediate clear; the arbitrary injected capacity-two assertion is deleted.
- Removed unused production inputs: capture.timeoutMs; session cache clock and capacity; snapshot-store capacity; ACP connection/peer defaultTimeoutMs forwarding. Production15s capture,90s ACP default and64/256 cache bounds are unchanged. Production8s probe handshake override and per-request deadlines remain. ACP peer teardown now closes every peer after each test, so a failed assertion cannot leave90s timer handles.
- Tightened child-before-handshake failure to CodexTransportClosedError and actual exit code0. Removed user-wording match from typed profile launch refusals. Removed immutable fixture-title and option-kind self-assertions. Replaced Codex helper-RPC ordering and profile Object.keys assertions with actual no-source-work and skill/tool isolation outcomes.
- No provider fixture, snapshot, dependency or configuration became orphaned in this scope. Existing fixture/privacy scan, protocol peers, real Linux process ownership/handover cases and the child-question workflow artifact remain necessary.
