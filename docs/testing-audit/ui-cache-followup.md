# Device-cache strict-bar follow-up

This is an override ledger for existing baseline `beb7516b` identities, not additional audit scope. Merge it over `ui-chat-lib.json` and the original auth owner’s rows; do not add counts twice.

Baseline declarations: 55; final declarations: 49. Dispositions: REWRITE 37, CONSOLIDATE 10, DELETE 1, KEEP 7. Six executions removed; zero new tests. Net follow-up code/test infrastructure change: −139 lines, including the relocated 88-line IndexedDB fixture.

Removed the production backend override/setter, IndexedDB factory argument and unused eviction callback. Internalized cache backend/schema/helper/constant exports that only tests imported. `linkThreadCache`, `clearThreadCache` and binding/scope remain the production-consumed interfaces. Removed the final `threadCacheIdle` export/function after verifying it had no production callers.

Both cache suites use fresh page module realms and the same public `indexedDB` platform boundary. Auth tests keep one platform factory with per-test raw store cleanup because the actual app store is imported statically. The original fake was moved once, with narrowly scoped request gates/failures and raw transaction fixture access; the two memory backends and auth key-deletion stub were removed. No dependency or production injection was added. The shared native fixture now tracks pending callbacks plus a generation counter, draining until a full event-loop turn schedules nothing. Deliberately held requests enter the runnable count when released. This replaces the production drain and five fixed settling rounds without sleeps.

Credible failures and six-bar evidence applying to every retained/rewritten owner:

- independentSource: AGENTS.md localStorage/bridge validation and secret privacy; README revocable sessions; packages/api agent-chat snapshot/fold version compatibility; documented cache policy and native IndexedDB schema; GUI authenticated resume and history-window contracts.

- credibleFailures: Copied pending actions execute before host confirmation; cached content survives sign-out/removal/revocation; another daemon’s entries are touched; legacy/malformed records enter state; snapshot/cursor or omitted-agent identity disagree; stale saves overwrite newer data; LRU/capacity/cadence/open-timeout policy fails. Each case gives its exact condition.

- independentOracle: Fixed legacy IndexedDB database/store/key/format bytes, authored frames/content/error/state, raw metadata corruption, controlled native IDB request failure/hang, literal cadence/size examples. No expectation reads the removed implementation helper or test-only override. FOLD_SNAPSHOT_VERSION is the separate public fold protocol used as an input version, never the cache owner’s oracle.

- stableSeam: Production linkThreadCache/clearThreadCache over global indexedDB and localStorage; actual thread-store remount and app-store authentication actions. Raw fixture setup/inspection uses native-style IDB transactions and existing IDB dependency fake.

- refactorResistance: No cache backend setter, factory parameter injection, helper export, map state injection or source grep. Fresh isolated page module instances preserve browser reload semantics without production reset hooks; externally persisted schema/keys and command receipts intentionally survive refactors.

- uniqueProtection: Cache file owns storage validation, cadence and eviction; device-store file owns stream/reload/action confirmation; auth file owns wiring of sign-out/removal/401 into clearing. Explicit consolidation rows identify the surviving owner; no full workflow is added or replayed at an extra layer.

Important preservation: native request hang still triggers bounded cold-open fallback and recovery; native read and factory-open refusals remain optional-cache failures; a gated native metadata request preserves the older-read/newer-save race; actual saved records verify schema versions/omitted rows, per-daemon privacy, history bounds, body deletion, count/size/LRU and cadence. The malformed-keyless-record variant was removed because a keyPath-key IndexedDB store cannot write it; malformed rows with valid keys, wrong versions/seq/thread IDs, invalid payloads and missing body still protect tolerant reads.
