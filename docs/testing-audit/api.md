## How to read the six behavioral bars

For every KEEP, REWRITE and surviving CONSOLIDATE row, the file evidence gives (1) the independent documented/public/protocol contract, (2) its concrete caller-visible failure family, (4) its shared public seam and consumers, and (6) the lowest owner and nonduplicate distinctions. The per-test name/input distinction and shown assertions identify its particular failure/oracle (2–3). Literal fixture expectations and standard JSON/UTF-8 bytes can disagree with the subject; lossless input/serialization invariants use independently authored input. Public values/bytes/actions survive an internal rename, clone, helper split or algorithm change (5). Unknown persisted-data and security shapes remain because actual provider/old-cache input reaches those seams. No retained test is justified by coverage percentage or by passing alone. A current public API/wire contract is used where a design document predates an additive feature; this ledger does not treat an obsolete design as authority over current supported protocol.

Isolated-unit credible failures were enumerated before retention in each file evidence block. Remaining lower-level cases own parser/type/lifecycle boundaries; integration tests are retained only for separate wiring/storage/security failures. Identified duplicate owners were checked directly and coordinated with their subsystem agents. DELETE rows name failed bars and survivors; risk is low for those exact assertions because independent data/security assertions remain. Risk of removing remaining protocol/persistence/privacy cases would be high.
