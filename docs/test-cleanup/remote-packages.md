## Six-bar justification for retained/reworked contracts

- **C — account defaults:** B1 persisted agent-account schema/config contract; B2 wrong initial default keys prevent family account selection; B3 literal empty accounts/null-family expectations are independently written; B4 `createDefaultAgentAccounts` is the config API used by daemon account initialization; B5 no source/call shape or generated catalogue oracle; B6 config is the lowest owner, parser tolerance tests exercise different supplied-document behavior. Low risk; only a comment changes.
- **A — account availability:** B1 GUI §3.4 and native adapter account capabilities; B2 OpenCode exposing an unsupported operation, or Codex refusing its supported operation, is visible in the composer chip; B3 literal booleans follow those capabilities, not imported mapping declarations; B4 `chatAccountSwitchSupported` is the client gate consumed by chat UI; B5 stable input/output decision across internal refactors; B6 lowest owner for pre-snapshot client availability, different from daemon authorization and account-list selection. Moderate risk; obsolete proxy-specific setup is removed.
- **P — usage delivery:** B1 provider wire `refIds` and GUI §7.7 ambient usage updates; B2 usage displayed against the wrong agent/missing window would remain stale; B3 expected Claude/window identifiers come from an independent wire fixture, not the fan-out algorithm; B4 provider read and registered ambient notification API used by the application; B5 no private counters, cache internals, or source assertions; B6 provider client owns wire-to-ambient routing, transport/parser tests do not deliver usage to consumers. Moderate risk; mock transport supplies only input and does not implement delivery.
- **R — resume routing:** B1 GUI §§5.2/5.3 require supported installed agents and provider-owned conversation resumes; B2 unavailable resume or wrong-provider resume is user-visible; B3 literal chosen IDs authored against two distinct provider fixtures; B4 `isResumableByInstalledAgent` and `isResumableByAgent` are the actual ProjectOverview/NewTabMenu filters; B5 only predicate outcomes and offered IDs matter, not markup or private mapping shape; B6 these filters own different constraints (installation versus grouping) at their lowest stable client seam. Moderate risk; no revived proxy wrappers or inventory checks.
- **W — workflow account family:** B1 workflow account policies apply only to managed Claude/Codex/Grok families, while tolerant stored chains may name removed agents; B2 assigning a retired/accountless agent another family's account gives the inspector a false account choice; B3 literal family/null results and supplied quota label are independent; B4 `accountFamily`/`scopedWindowLabels` feed ChainEditor account-policy controls; B5 no declaration equality or mock implementation; B6 lowest owner of client family/usage grouping, distinct from runtime selection and persisted-schema tolerance. Moderate risk; keep arbitrary stored agent strings parseable rather than narrowing storage to the current catalogue.
