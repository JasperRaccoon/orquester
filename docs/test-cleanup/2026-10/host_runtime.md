# Host runtime test cleanup

Scope: all 41 assigned host-runtime test files; 743 baseline named declarations (parameterized declarations counted once). Contract/assertion-level review covered each declaration; detailed fixture/owner inspection focused on changed tests and expensive paths. Per-case rows retain exact baseline names, including names changed by rewrites. The audit does not claim new external-provider E2E captures.

## Dispositions

CONSOLIDATE: 8, DELETE: 6, KEEP: 705, OPTIMIZE: 5, REWRITE: 19. Twelve declarations were removed: six deletions and six removed duplicate executions; two surviving owners are also classified CONSOLIDATE.

Test LOC: 24,482 → 24,295 (-187). Report/documentation LOC is excluded. Production source changes remove unused exports/options/accessors; no runtime decision or provider protocol behavior changes.

## Shared behavioral bar and boundaries

Each file section supplies the independent requirement, stable seam and ownership argument for its cases. Its rows supply the concrete failure and literal oracle. Expected values come from fixed input data, historical compatibility bytes, conservation of recorded input rows, or documented status/ordering rules; they are not computed using the asserted projection. Public typed boundaries and durable/wire outputs survive behavior-preserving private refactors. Unchanged cases retain no arbitrary sleeps; mock clocks, drains, gates and actual closure receipts provide deterministic synchronization. Production callers are main.ts, server/http-server.ts, orchestrator.ts, provider adapters and the daemon AgentHostClient; test-only exported accessors/options identified below had no repository callers after cleanup.

## Removed support and production seams

- Removed SessionToolCredentials.size; unused CreateSessionToolsHostOptions.credentials injection and unused credentials re-export.
- Removed SessionSecretRedactor.holds; release is verified at maskText instead.
- Made chatShape, chatDescription, compactToolEntry, clipForkMessage, FORK_TRANSCRIPT_MESSAGE_MAX_CHARS, UNCHECKED_BACKGROUND_TTL_MS and the three WIRE_WINDOW bounds private after repository-wide caller searches. serializeChatTools stays exported for actual MCP serialization/support consumers and registry budget verification.
- Removed bespoke provider registry fixture/dynamic imports from fix-wave; reused existing withRegistry fixture in its owner. No shared fixture, dependency, snapshot or package configuration became unused.

## Performance and validation

Root orchestrates all tests (one test run per worktree), with TSX_DISABLE_CACHE=1 and package default concurrency 4. Baseline full-suite timings come from /tmp/orquester-test-audit/baseline.log. Most expensive case in this scope: provider array preservation in fix-wave, 6221.27 ms; moved to provider-snapshots. Real teardown lifecycle cases measured 1751.63–3383.85 ms and remain because only real composition-root/process shutdown can detect overlapping stopAll and consumption order. Attachment cap cases measured 144.89, 115.53 and 129.44 ms; history import measured 95.73 ms.
Sparse attachment files avoid allocating/writing 33 MiB of zeros while retaining real stat enforcement. Replay progress input shrank 1200→504 events, the smallest full-turn fixture above the 500-event chunk. These are work reductions, not unmeasured CI speed claims. Final suite/focused timings and mutation validation are recorded below when scheduled by root. No full-suite speedup is claimed here before comparable final measurement.
