Execution measurement and final validation are coordinated by the root agent; no concurrent test run was started during the baseline hold. See the final validation paragraph below for actual commands/results after the scheduled gate. No isolated or CI speedup is claimed without measurement.

## Shared page-loader optimization

`testing/isolated-page.ts` now recycles tsx namespaces only after disposal has evicted that page’s JS/TS module instances. Live pages use distinct namespaces. Repeated disposal is harmless, and disposed page getters reject access. Unlike the previous snapshot-based cache cleanup, disposal leaves other live pages’ modules intact. No production code, storage, fixture state or mutable module instance is reused.

The installed tsx 4.22.4 implementation uses a process-local transform Map even with `TSX_DISABLE_CACHE=1`, and keys transforms by namespace. Fresh random namespaces defeated that cache. Recycling namespace slots permits compiled-code reuse while preserving fresh module execution; disk caching remains disabled. The seven helper entrypoints reach 136 local runtime modules through static imports/exports, with no delayed dynamic imports or requires that could attach old callbacks to a recycled namespace. Shared unnamespaced JSON/native handling follows tsx’s existing behavior. This optimization applies to retained store/reload/outbox consumers; case dispositions below describe their primary behavioral audit decisions, not a count of every case benefiting from shared startup work.

The temporary real-store probe passed: two live pages route uploads to their own transports and retain independent providers/send tokens/drafts; a replacement page reads persisted draft/outbox storage but starts with fresh registry/provider/send state; disposing the old page twice leaves both live pages intact; settling its old send token leaves the replacement page’s send open. No permanent cache-shape or pool-inventory tests were added.

Three alternating original/pooled measurements used separate Node 24.22.1 processes, `TSX_DISABLE_CACHE=1`, the same current production graph and sequential six-page workload. The host exposes 16 processors; full focused tests use four file workers. Each process has one cold page and five later pages. GNU time records wall/CPU/RSS; wall variance is visible in both variants.

| Six-page loader benchmark | Original | Pooled | Measured reduction |
| --- | --- | --- | --- |
| Median process wall time | 22.78 s (21.59–31.57) | 9.07 s (9.04–11.37) | 13.71 s / 60.18% |

These are measured loader-workload improvements, not whole-suite or CI savings. Cold graph compilation and fresh module execution remain necessary; simultaneously live pages need distinct compiled namespaces. Raw measurements are `/tmp/orquester-test-audit/page-profiles.json`; the final repository-wide wall comparison belongs to the root report.

## Behavioral bar for retained owners

For each file below, the listed independent source establishes B1. Each row records the exact scenario and concrete oracle for B2/B3. The named seam is the caller-consumed state/protocol boundary (B4), and the callers establish that it is live production code. Retained expectations concern data, identity routing, persistence, authorization or state transitions; they survive private identifier, algorithm and rendering refactors (B5). B6 is reviewed at the owner: API schema/fold tests establish protocol parsing and server state; these UI cases establish client selection, stream consumption or command/persistence wiring. Unit projection cases keep specific input/state outcomes at the lowest seam; integration cases survive only where omitted wiring, ordering or lifecycle synchronization creates an additional failure. Shared fixtures isolate dependencies and never calculate the asserted business decision. Test-specific production-derived oracles/identity checks are removed in the decisions listed below.

Risk: low for copy/identity/inventory deletion; moderate for rewriting retries/cache validation, so loader, cache, store and dependent UI gates must pass. Real history bridge retention/cap scenarios and reload/device-cache cases remain intentionally expensive because they uniquely check loss/duplication, cursor ordering, stale authorization and complete lifecycle wiring. Fake IndexedDB validates the adapter contract, not browser engine conformance.
