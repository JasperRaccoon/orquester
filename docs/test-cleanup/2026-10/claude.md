# Claude adapter test cleanup — October 2026

Audit scope: all 494 named declarations in 21 Claude adapter test files (13,784 baseline test lines), their production owners, current wire contracts, and test/fixtures/claude/README.md provenance. Root coordinated the full-suite baseline and integration gates; this scope did not start a daemon or alter live state.

Disposition counts (baseline declarations; CONSOLIDATE includes removed cases and surviving owners): KEEP 456, CONSOLIDATE 27, OPTIMIZE 5, REWRITE 5, DELETE 1. Fifteen declarations are removed; 479 survive. Test lines decrease from 13,784 to 13,546 (net −238). No fixture, snapshot, dependency or test configuration became orphaned. Removed support comprises the session-tools fakeContext helper, the test-only relistTimeoutMs timeout override, and four non-consumed production exports (compareVersions, toSessionPermissionUpdates, ClaudeLocalProcess, EXIT_AFTER_STDERR_MS); production still uses the private functions/classes/constants.

The six behavioral requirements are assessed jointly by the per-file rationale and every exact declaration/oracle row below: (1) an independent spec/protocol/config source, (2) the concrete bad caller-visible outcome named by the declaration, (3) the literal/captured expected assertion shown in the row, (4) the listed public API/protocol/file seam, (5) observations of returned data/events/files rather than private call layout, and (6) the unique owner/failure described for that file and the specific case. Synthetic input is not a synthetic oracle: test doubles script only the external provider response; the real adapter constructs the observed result. Repeated cases are explicitly assigned their surviving owner rather than retained for coverage. Risk is low for deletion/consolidation: meaningful assertions move to the same public seam or already remain in a strictly stronger scenario. The optimized high-volume scenarios retain real read/frame boundaries.
