# MCP test audit and cleanup

Audited all **762 baseline named test declarations in 52 files**, reading test bodies with production owners and current independent contracts. Parameterized declarations count once; runtime test count is larger. Final source has 724 declarations (38 fewer). Every baseline declaration is listed below, including renamed/deleted cases.

Dispositions: **DELETE: 23**, **REWRITE: 62**, **OPTIMIZE: 5**, **CONSOLIDATE: 24**, **KEEP: 648**.
Test source delta: **+387/−1419 lines, net -1032 LOC**. Consolidation counts include removed cases and surviving owners; this does not mean every CONSOLIDATE row is deleted. Shared fixture optimizations are reported separately from direct per-case OPTIMIZE decisions.

## Implemented cleanup

- Removed broad source/AST/import/export/count/doc-prose scans and replaced repeated registry/family SDK constructions with one actual external/chat serializer contract owner. Literal external API required-input/name/annotation wire contract remains in server.test.ts.
- Removed duplicate review conversation E2E/picker/unknown-mode scenarios, direct formatting-helper cases, unused workflow union/snapshot wrappers, duplicate private path assertions and repeated Grok normalization replay.
- Kept real workflows, native profile writes, prompt ownership, principal trust boundaries, token security, filesystem containment, durable history/index recovery, provider formats and live-output paging. Tests observe semantic bytes/records/errors/effects, not layout or incidental prose.
- Replaced a lost-event queue test race with subscription barriers; cut repeated Unicode alignment cycles while retaining large cap-crossing fixtures. Oversize generic attachment uses sparse file metadata instead of constructing 13 MiB base64. Real-server harnesses use a write sink instead of leaking /dev/null WriteStreams.
- Fixed an OpenCode negative test that could pass for unknown-agent/wrong-account errors by providing a valid enabled OpenCode/system-account fixture; retained intended INVALID_ARGUMENT guard.
- Removed remaining whole approval-title/scope prose comparisons while retaining target/global/provider/repository identities and visible plan data. Removed four workflow actions whose only outcome was a section-title check; the unique create/grant-recording checks survive.
- Rewrote knowledge text assertions around exact backend citation/body/input bytes and semantic metadata/status/continuation, removing decorative headings and punctuation freezes.
- Rewrote private saved-prompts Map mutation through persisted JSON and public load. Moved distant diff change protection to actual approval-card owner; removed exact context/prose snapshots.
- Removed production-only-for-tests/dead seams: externalMcpToolNames, exported buildCatalog/TOOL_NAME_PATTERN, principal clock setter/live count, workflowProjectUnion, runningTurnPlans/runningExchange, ownChildren export, executor NEW_SESSION re-export, workflow and saved-prompt unifiedDiff exports, unused profile sha256, profile looksLikeSecret/workflow blockUsesSecrets exports (security checks now at surviving card/policy owners), visuals guidance constants, secret note constants, durationLabel/box timeout, nine unused knowledge helper/limit exports and git-limit exports. The legitimately reused profile unifiedDiff remains public. Simplified changesSecretUse to its only real caller shape. API owner removed unused toolset inventory helpers; host owner privatized compactToolEntry; approval owner privatized WORKFLOW_GRANT_NOTICE.

## Retention proof convention

Each section below supplies the shared six-bar proof: independently documented API/protocol/security/storage source; public/stable observed seam; independent literal expected values and supplied fixture bytes/records (length arithmetic measures fixture data, not production algorithms); semantic assertions survive identifier/control-flow/module refactors; specific caller-visible failure and unique ownership per row; production consumers described separately from test-only seams. Backend/approval doubles supply external data/answers, not the behavior under assertion. Each row adds its exact baseline name and concrete failure/deletion reason. Critical retained failures are high impact; changes are limited to test setup/oracles/dead seams, with affected/full tests and typecheck required before integration.
