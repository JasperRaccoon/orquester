# Codex adapter test cleanup — October 2026

## Scope and method

Audited all **334 baseline named declarations (371 expanded runtime cases)** across the 17 assigned Codex test files, reading bodies, production owners and `apps/daemon/test/fixtures/codex/README.md`. Parameterized declarations are single ledger rows; their concrete status/mode/request-type variants are retained unless the row explicitly narrows a matrix. This ledger records baseline names/line numbers, so deleted tests remain traceable after source moves.

Changes remove **19 separate declarations/executions**, including 7 DELETE and 12 CONSOLIDATE removals; 11 surviving CONSOLIDATE owners absorb assertions. Three declarations are REWRITE, six OPTIMIZE, and 295 KEEP. Final declarations: **315**, expanded cases: **352**. Disposition counts overlap neither removed nor surviving rows. Executions removed inside retained cases are additional: nine malformed-cursor child launches, one duplicate late-answer child launch, and three extra retention probes.

Test LOC: **net −267** across nine changed test files.

No provider behavior, generated bindings, fixtures, snapshots, dependencies or runner configuration changes. Removed support is limited to unused profile-test imports, the `seeded`/`accountHome` fixture options, unused returned fixture fields and empty suite wrapper. Fork tests now remove their temporary mock directories via per-test teardown. The malformed cursor matrix moved to the existing production-used pure cursor reader; two actual session fallback examples retain caller wiring.

## Evidence shared by the per-case ledger

The row's concrete failure/oracle plus its file rationale below constitute its six-part decision. Sources were checked against current source and wire contracts; previous audit reports are not treated as evidence.

1. **Independent contract:** GUI design `docs/superpowers/specs/2026-09-21-agent-chat-gui-design.md`, especially §3.1 child supervision/deadlines, §4.1 adapter/session/resume surface, §4.2 runtime events, §4.3 approval decisions, §4.4 permission modes, §4.5 Codex protocol, §4.6 catalog/skill contracts and §7.3/§7.6 history/drill-in; goal design `2026-09-24-agent-goals-design.md` §6.2; visuals/session-tools design `2026-10-14-agent-visuals-and-session-tools-design.md`; unified MCP design `2026-10-15-unified-orquester-mcp-design.md` §12.1; profiles design `2026-10-18-agent-profiles-design.md` §6.2. `packages/api/src/agent-chat/adapter-types.ts`, `runtime-events.ts`, `wire.ts` and `apps/daemon/src/agent-host/adapter.ts` define the caller-facing data/interfaces. The fixture README distinguishes recorded 0.154/0.159 traffic from generated-schema/source-derived child/goal behavior; synthetic tests do not claim a live capture exists.
2. **Real failure:** Each retained row names the visible/caller failure and actual field, wire byte, state, transcript result, error or ordering that detects it. Assertions on an externally supplied provider reason/prompt are data preservation, not application copy snapshots.
3. **Independent oracle:** Fixed protocol enums, explicit frame objects, literal expected text from committed recorded traffic, fixed byte/time/token values and required relationships supply expected values. Expected results are not obtained by invoking the same production transformer. The rate-limit ID fixture now uses a nondefault name; timestamp conversion uses a literal ISO result. MCP dependencies supply wire inputs or attachment IDs, while the real transport/session/capture/ingestion being asserted remains active.
4. **Stable seam:** Provider frame → normalized RuntimeEvent, native history → projected events, AgentAdapter/CodexSession operations → actual child NDJSON/stdout/stderr/env, or async iteration/explicit pure state-machine input → contract result. No source grep, private field inventory, export-count, markup geometry or collaborator-call snapshot remains in this scope.
5. **Refactor resistance:** Assertions concern protocol spelling/correlation, authorized operation order, output ownership/content, persisted history and public normalized status. Functions may be reorganized internally without changing the observed behavior; the one private queue-cap tuning assertion was deleted for failing this requirement.
6. **Unique ownership:** The row states its distinct trigger or why a stronger owner subsumes it. Raw provider mapping, session bookkeeping, and composed ingestion/orchestrator tests coexist only where their assertions cover different failure modes (for example raw namespaced chunks versus roster-title translation versus pending-card survival through the orchestrator sweep). Removed setups move any unique assertion into the existing owner rather than leave a gap.
