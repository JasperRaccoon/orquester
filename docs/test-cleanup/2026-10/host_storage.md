## Behavioral review method

For every retained declaration the row names the exact contractual behavior and gives its concrete independent output/error oracle. The file rationale supplies the six shared requirements: (1) independent design/API/protocol/persistence source, (2) the recognizable failure named by the case, (3) literal arranged data, immutable prior state, real physical bytes or captured provider frames as the oracle, (4) the stable seam listed below, (5) output comparisons survive internal refactors, and (6) the distinct owner/failure versus adjacent layers. Mocks replace external OS/provider/time dependencies only; the operation deciding the asserted result remains real. Risk is data loss, leaked credentials, wrong ownership, wrong UI state or stale/missing results as named by each row; no production-facing API/behavior is removed.

Production callers are the orchestrator/host, provider adapters, daemon supervisor and the published ThreadStore/ThreadIndex services. Removed exports/hooks were checked repository-wide: isSharedDaemon and SHARED_DAEMON_ENV_VARS had no external production caller; ReplayCursorRing.size/custom capacity and REPLAY_CURSOR_CAPACITY export had none; planMcpBridges.newServerId had only the test caller; PROVIDER_CHILD_NICENESS export had no external caller; onLogRead had only the replay-cursor test callers. Internal behavior remains, without those test-only entry points. Read-cost contracts now observe actual filesystem bytes through transparent native filesystem instrumentation owned by the test, with mocks restored and builtin ESM exports synchronized after each case. Byte budgets avoid exact native call counts, allowing equivalent whole-file and cursor chunking.
