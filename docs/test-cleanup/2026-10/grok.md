## Performance and validation

Baseline: root ran the unmodified full suite with package runner defaults, TSX_DISABLE_CACHE=1 and four files per package. No Grok baseline failure was observed. The no-handshake scenario took **30,091.385281 ms**; the live snapshot catalog scenario took **4,271.328026 ms**; the two redundant prompt matrices took **304.744956 + 279.036215 ms**, respectively. These are baseline per-case costs, not additive suite wall-clock savings.

The handshake now advances virtual time after the real outgoing initialize receipt, which follows arming the ACP deadline, then resets timers before awaiting real child teardown. On Linux it also verifies the actual marked CLI is gone before failed start returns. The ACP request timeout uses controlled time; the catalog scenario uses a realistic noninteractive wrapper that answers version/models/inspect promptly. Repeated captures and child startups are consolidated. Bounded-output fixtures still cross the same asserted caps with smaller allocations.

Intentionally retained expensive coverage: six session-replay scenarios (baseline 1.65–4.52s each) protect recorded transport order/turn boundaries; Linux helper/work-lifetime scenarios (roughly 0.9–2.3s each) launch actual detached children and prove deploys preserve running work while user ends stop it. Removing real process checks or replay synchronization would weaken their contract. Live real-Grok isolation remains opt-in; default suite skipped it, so no claim of real-CLI verification is made.

Final isolated timing, net test LOC and exact validation commands/results are recorded below. Full-suite wall-clock/CI measurements belong to the root integration report; no CI improvement is extrapolated from isolated cases.
