# Workflow UI test cleanup — October 2026

Scope: all 31 assigned baseline files, 199 named declarations, 3,621 baseline test lines. Every case and its production owner were read; historical audit ledgers were context only. No cases are unreviewed. Root owns repository-wide profiling, gates, integration and delivery.

The independent workflow specification is [automated workflows](../../superpowers/specs/2026-09-28-automated-workflows-design.md), checked against current API/config/wire owners before applying it. Profile validation additionally follows [MCP documentation](../../orquester-mcp.md). AGENTS.md supplies tolerant persisted data, browser payload validation, connection isolation and protocol boundaries.

The following six-part reasoning applies to each retained row together with its concrete contract, failure and file rationale: (1) the listed independent specification/protocol/schema/public API requires the result; (2) the named wrong data, action or navigation reaches a real production caller; (3) expected values are literal fixtures, calendar/unit facts or independently supplied protocol data, never generated by the code being tested; (4) tests invoke production semantic actions/parsers and observe consumed data or protocol bytes; (5) assertions survive identifier, algorithm and rendering refactors, without private call-shape, CSS/markup or object-identity requirements; (6) each row identifies a distinct failure at that semantic owner. Where stronger coverage absorbs a probe, the declaration is consolidated and the surviving owner is named. Shared validators/daemon execution tests do not observe UI request construction, state races or derived view data.

Credible failure modes considered before retaining isolated units: wrong graph paths; lost edits or revision races; malformed wire/storage values entering typed state; wrong account/model selection; invalid template insertion or copied paths; skipped/truncated/wrong log/output data; stale or misattributed run state; lost/duplicate failure alerts; wrong project/run navigation. No test survives only for coverage or because it passes.

## Implemented changes

- Consolidate the standalone app channel-forwarding probe into the existing tab open and rename/delete workflows, including module-store assertions.
- Inspect PUT metadata exclusions in the existing autosave request rather than loading/saving another editor.
- Move the three pin-output cases to their existing inspector-data owner, removing a test worker; tighten the malformed-answer rejection so an accidental TypeError cannot pass.
- Move run selection to run-view tests and verify selected-block preservation/fallback using its real finished timeline. Remove the duplicate synthetic TimelineItem fixture and a test worker.
- Replace direct history seal invocation with undo/redo/new-edit behavior; make the internal history seal private and remove the unused editor sealHistory wrapper after repository-wide caller search.

Production changes remove unused surface only: no execution behavior, wire/config format or API request semantics change. Shared fixture testing.ts, dependencies, snapshots and configuration remain needed; none became orphaned.
