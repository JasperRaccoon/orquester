# Agent config and native profile isolation audit

The assigned scope is all 341 baseline named declarations in 34 files (10,075 baseline test lines). Each declaration was read with its fixtures, production boundary and the applicable native-format/product requirements. The ledger below is exhaustive for this scope; it does not classify tests owned by the other workstreams.

## Contract evidence and six-part retention rationale

Independent requirements are [the approved Agent config design](../../superpowers/specs/2026-09-28-agent-profile-design.md), [Agent Profiles isolation](../../superpowers/specs/2026-10-18-agent-profiles-design.md), [MCP approval and daemon-pointing rules](../../superpowers/specs/2026-10-15-unified-orquester-mcp-design.md), the repository's security/runtime rules in [AGENTS.md](../../../AGENTS.md), and the native-format observations/recorded fixtures identified in the tests and [isolation README](../../../apps/daemon/src/agent-isolation/README.md). Current native file owners and wire contracts were checked alongside those requirements; obsolete placement wording in the September design is superseded by the October design and is not asserted.

The numbered ledger rows supply the specific recognizable regression and expected outcome. The shared rationale here supplies contract source, stable seam, oracle, refactor resistance and uniqueness for each file. A surviving test's fixed expected values come from its native-format/product requirement and deliberately arranged input bytes; they are not read from a production branch or recomputed by the production helper. Filesystem layout assertions remain only where the agent actually loads those paths, native merge order affects precedence, or exact original bytes are promised for safe config editing/stash restoration. No UI geometry, markup snapshots, export inventory or uncontracted wording is preserved in this scope.

### Isolation primitives

`agent-isolation/claude-names.test.ts` observes exported loader-name/config discovery boundaries used by Claude's profile launcher and profile/plugin preparers. The independent loader probes are documented in the isolation README and Profiles §6.1; expected IDs, namespace separators, ancestor stopping rules and installed-plugin v2 records are literal fixture expectations. These tests detect missing/incorrect context allowance. The former oversized-read case was removed: it derives its threshold and requested-length oracle from the production constant and asserts the cap+1 strategy. The exact 64 MiB helper threshold has no independent specification; shared ProjectFs tests own mandatory finite bounded reads and overlong-reply refusal. A launcher-level manifest test cannot enumerate all naming, file and ancestor cases without duplicating more expensive setup. Filesystem `ClaudeNamesFs` is the actual host/remote ProjectFs boundary, not a test-only export. Refactoring scanners or helper names while preserving native IDs/files remains valid.

`agent-isolation/claude-plugin.test.ts` owns generation of the actual native plugin directory and returned SDK allowlist (Profiles §6.1). It checks specified on-disk paths/content, security treatment of symlinks, whole-kit replacement and refusal that preserves the previous usable kit. It does not assert staging names or internal call order. The generated tree is consumed by Claude, and a launcher mock cannot prove its content. The empty kit and invalid kit have distinct loader/pre-write failure modes.

`agent-isolation/codex-seed.test.ts` owns Codex DB seeding and shared-history linking (Profiles §6.2). A subprocess fixture obeys the independently recorded initialize/initialized/EOF protocol and records what sessions directory the CLI saw. Expected DB presence, shared rollout bytes, process termination, refusal/retry states and concurrent one-run behavior can disagree with the implementation. Launch-level tests do not run the seeder through every crash/link/version state. The existing-seeded fixture now arranges the prerequisite state directly rather than paying for a redundant initialize cycle. Real subprocess execution remains for handshake, timeout and EOF behavior.

`agent-isolation/grok.test.ts` owns exact global exclusion paths, plugin discovery results, rendered native TOML and compat environment keys (Profiles §6.3). Fixed paths/names and parsed literal expected TOML are independent of the builder; native TOML formatting is free to change. Parser-only normalization now uses the lowest stable parser seam; one real child still proves argv/environment/cwd and separate children prove error/timeout handling. The environment-key literals are public Grok protocol keys, so they survive TypeScript identifier renames. The old key-count inventory and builder-derived oracle were removed. Higher-level launcher tests cannot replace these exact configuration/exclusion cases without much larger fixtures.

`agent-isolation/opencode-home.test.ts` owns detection of loadable global home config and the actual two-run override canary protocol (Profiles §6.4 and documented OpenCode probe). Its fake CLI reads the literal `OPENCODE_TEST_HOME` key independently and its result differs for ignored overrides, an inconclusive control, malformed output and process failure. That probe already detects a wrong variable name, so the standalone constant assertion was deleted. The native startup capability is uniquely observable here; the fixture never uses a real account or network registry.

`agent-isolation/runtime-settings.test.ts` owns runtime-policy preservation versus global-item isolation (Profiles §6.0). Each native-shaped fixture has a literal expected output including unknown runtime keys, nested named-profile trust/limits and vendor-specific item exclusions. Deep-copy mutation verifies shared Global settings remain unchanged. Production-derived dropped-map loops were redundant with these fixed outputs and could not independently detect a wrong dropped-key list, so they and their otherwise unused exports were removed. Higher-level profile preparation tests own wiring; these are the lowest owner of exhaustive filtering and copy behavior.

`agent-isolation/xdg-shadow.test.ts` owns the real symlinked XDG view (Profiles §6.4): expected symlink targets, source-tree invariance, private mode, convergence, preservation of real tool-created entries and refusal of overlapping roots. Those are native filesystem contracts independent of loop structure and cannot be proved by a launcher environment mock. The excluded-only case duplicated the mixed-entry and refresh exclusions and was deleted; absence of the real directory remains a distinct supported startup case.

### Native Agent config adapters

`agent-profile/adapters/claude/claude-json.test.ts` owns Claude's live-state lock/transaction boundary (Agent config §§4.1, 4.5). Proper-lockfile's real lock protocol is exercised; fixed concurrent file edits and parse failures supply independent oracles for latest-state reads, data preservation, secure creation, no-op/failure cleanup and compromised locks. Filesystem interception only signals/provokes actual lock contention/compromise; it does not implement a write or desired result. Adapter tests cannot replace concurrent-lock failure protection.

`agent-profile/adapters/claude/index.test.ts`, `adapters/codex/index.test.ts`, `adapters/grok/index.test.ts` and `adapters/opencode/index.test.ts` each own their vendor's `ProfileAdapter` API/native-file boundary (Agent config §3 matrix, §§4.3–4.6, §6; additional native probes recorded in each test/source). Their literal native fixtures and file/revision/error results catch vendor-specific failures: wrong source ownership, foreign edits, managed-item mutation, wrong disable mechanism, secret leaks, stale writes, incorrect rename/copy/import and destructive malformed-file handling. CLI/app-server fixtures isolate the external vendor dependency using independently documented argv/NDJSON shapes; they do not replace the adapter transformations, validation, persistence, conflict logic or redaction under assertion. Assertions on argv/RPC fields are retained where those are the vendor's public CLI/protocol, not private collaborator method shapes. Ordinary wrapper forwarding alone is not the justification. Distinct vendors have different storage, toggle and trust semantics, so identical business verbs are not duplicate protection. Broad service/E2E workflows select a representative native path, while these lower native owners cover each vendor's remaining exact contract cases and failure modes. Identifiers and internal decomposition may change without changing the observed files, public item results or native wire fields. Real disk writes and per-test temporary homes keep isolation independent. Profiling identified repeated fake Grok inspect startups as the largest retained cost; file/metadata cases now receive the same arranged raw native JSON through the existing CLI result boundary. The real subprocess remains in the snapshot argv/env/cwd owner, inspect-failure fallback and every actual plugin/marketplace command. This stub supplies external dependency data only: production still parses it, reads/writes files, calculates ownership/revisions, validates and applies the asserted mutations. The stale-inspect race already used a controlled CLI boundary and is unchanged.

`adapters/codex/codex-config-client.test.ts` owns the separately specified child lifecycle/config RPC transport: CODEX_HOME, one initialize, reusable process, idle deadlines, pending calls, timeout/respawn, missing binary and native error mapping (Agent config §4.1). Real subprocesses provide externally observable PID/process termination and config responses; controlled timers remove elapsed-time cost. Native key-path literals protect the actual wire format. Adapter tests intentionally suppress these deadlines, so they do not supersede lifecycle protection.

`adapters/codex/hooks.test.ts` owns persisted hook identities, native trust hashes and re-keying (Agent config §4.6). Hash oracles are literal vectors observed from codex-cli 0.155.1, including timeout/event/matcher variations, not copied from the implementation. Fixed native state-key examples and independently arranged off/stale-trust values catch positional privilege transfer, duplicate-handler switch mixups and colon-path corruption. Adapter hook tests prove wiring/account reach; this cheapest seam uniquely checks the complete observed hash vector and re-keying corner cases.

`adapters/grok/inspect.test.ts` checks normalization against the recorded real Grok report under `apps/daemon/test/fixtures/grok/12-cli-text/grok-inspect.json`; the second case covers plugin-origin identity and fail-closed malformed reports absent from the recorded capture. A fixture generated by an adapter test cannot replace a real protocol capture. Reader refactors are free provided the normalized stable result remains identical.

`adapters/grok/toml-patch.test.ts` and `adapters/opencode/jsonc.test.ts` own comment/content-preserving native document editing (Agent config §4.1, §4.5). Literal human-authored syntax variants, parseable expected values and preservation of neighboring text catch malformed removals, inline/trailing-comma failure, lost same-line comments and CRLF rewrites. They observe document transformations, not CST classes or parser calls, and survive parser-library replacement. Adapter lifecycle tests cover other syntax arrangements, so these specific insertion/removal variants remain distinct native config contracts rather than repeated CRUD workflows.

### Conversion, detection, HTTP and critical workflows

`agent-profile/convert.test.ts` owns the portable conversion boundary (Agent config §6 and wire PortableItem formats). Literal mapped metadata/body/timeout/transport expectations and original source bytes catch wrong destination semantics or accidental foreign-source mutation. Inner-symlink refusal is specific to a converter-owned copy, while an allowed root symlink is a distinct source path. Native adapter tests own receipt/persistence; they do not replace portable format mapping before receipt.

`agent-profile/daemon-mcp.test.ts` owns daemon-pointing detection (MCP §§12.1, 14.2.8) and its HTTP/socket authorization boundary. Literal URLs, verified fake bearer identity, native config shapes and real contained/symlinked directories supply independent expected classifications. It catches privileged endpoint exposure, secret serialization/logging, incomplete inherited/account scans and sandbox escape. URL/trust examples are cheap lower owners of exhaustive native address/loader forms; integration detects correct file aggregation and transports. Generic MCP mocks do not reproduce those path/security semantics.

`agent-profile/e2e-mcp.test.ts` retains three critical real-service/native-storage workflows: masked partial MCP edits including raw credential URL preservation, exact approval/write skill content with stale refusal, and keep-both batches through real Claude imports/naming. These are cross-boundary secret/approval contracts (MCP §§7.1–7.2, 14.2.11), rather than repetitions of native CRUD. An existing workflow now uses reversed picks, a name claimed by an earlier create, and an unpicked reserved skill to absorb the useful contract from the deleted fake-naming test. Its card-versus-written-bytes assertion plus literal two-body → alpha-3 / one-body → alpha-4 oracles detect incorrect preview association or import order. The section display order is deliberately unconstrained: cards enumerate scan candidates while names are assigned in selection order. A JSON verification artifact is deliberately retained by the first workflow and printed by the test; the other cases verify exact files during execution. Production network calls are limited to its ephemeral loopback MCP server.

`agent-profile/homes.test.ts` owns the documented native environment/home-resolution contract (Agent config §3, Profiles §6). Literal unset, explicit, empty and XDG/additive-root examples catch wrong files being edited; other adapter fixtures supply homes directly and therefore cannot supersede this resolver. Expected paths are platform-safe joins of independent literal directory names, independent of production resolution.

`agent-profile/import.test.ts` owns Git/ZIP/Markdown import lifecycle/security (Agent config §6). Fixed URL/filename examples, actual native tree bytes, explicit expiry clocks, limits, agent scope, release state and one real local Git repository detect credible unsafe writes, incorrect conversion, resource leaks and native clone protocol failures. The injected clone copies source fixtures or fails explicitly; it does not implement scanning, containment, conversion or cleanup. Real Git is necessary once to verify actual clone flags/protocol enforcement; other lifecycle tests avoid network/process setup. Default ZIP cap verification now uses cap-specific error oracles and a tiny over-declared header so parser-size mismatch cannot impersonate a limit failure; configured small-cap coverage retains actual compressed-data handling. Sparse checkout files already avoid bulk I/O for the independent 50 MiB checkout-size contract.

`agent-profile/preview-reads.test.ts` owns exact approval source content/provenance, native plugin capability enumeration/cache containment and service preview transformation (MCP §§7.1–7.2, 12.1). Actual text/bytes/commits, fixed expected capability names, real symlinks and wire error/status/query examples catch stale/incomplete/unpinned/misnamed approvals or secret leaks. The low-level reader tests enumerate native source formats; service previews uniquely enforce target filenames and temporary-export disposal. The deleted fake suffix algorithm/one-call-count test's real selected-pick ordering and unpicked-candidate contract now runs through the existing real E2E owner. The remaining fake converter in copy-preview tests does not produce the asserted preview tree, rename or cleanup; those are production service behavior.

`agent-profile/routes.test.ts` owns HTTP request/response contracts and streamed upload lifecycle (shared API route definitions; Agent config §§4.5, 4.9; AGENTS.md binary-upload/secret rules). Arranged service outcomes isolate the lower native layer while the real Fastify route decodes IDs, validates payloads, maps errors, caps bodies and handles actual temporary upload bytes. Exact status/error codes and no-secret responses are independent wire oracles. Argument checks remain only for intact decoded IDs/multiline text/empty revisions, whose loss changes caller-visible behavior. Native adapter/E2E tests cannot replace invalid HTTP parsing and pre-body connection safety.

`agent-profile/service.test.ts` owns per-agent queuing, availability/capability checks, snapshot aggregation/revisions, lifecycle publication, copy/import cleanup and watch/recycle lifecycle (Agent config §§4.2–4.8). Controlled adapters/watch events isolate native I/O; they do not implement the production service's queues, revision arbitration, event suppression, partial-failure settlement, cleanup or watcher rearming. Fixed outputs/events and actual temporary-directory existence supply independent oracles; the real fs.watch case checks platform integration once. Concurrency gates and virtual timers keep the remaining races deterministic without sleep polling. Generic transport and vendor tests bypass or do not enumerate those service races, so no stronger owner supersedes them.

### Shared filesystem and parsing infrastructure

`infra/backups.test.ts` owns the documented recovery ring (Agent config §§4.1, 4.5): actual copied bytes/modes/links, exactly 50 retained versions per agent and same-time collision preservation. `infra/fs-write.test.ts` owns atomic native writes/deletes and verified-write rollback against real symlinked/dangling/cyclic paths. `infra/stash.test.ts` owns persisted off/on compatibility (Agent config §4.4): manifest identity/version, bytes/modes/links, colliding/foreign/corrupt entries, long logical IDs and EXDEV fallback on distinct real filesystems. These tests use actual temporary files and fixed expected errors/content; changing internal copy/rename helpers is safe while promised filesystem behavior survives. Adapter tests check vendor mapping to these operations, but cannot replace this shared owner's complete path, corruption and recovery matrix. These are also production dependencies of session-profile storage/export/preparation, increasing the cost of losing lowest-seam protection.

`infra/cli-runner.test.ts` owns the actual child process/environment/output/error boundary (Agent config §4.1 and AGENTS.md secret/process rules). It verifies literal hostile argv, actual stdin/env, real process exit/signal and independently fixed redaction expectations. The SIGTERM-ignore case waits for a real ready event before advancing virtual timeout/grace; the observed SIGKILL result is still real. The output cap now checks the documented default directly and drops the unused injected cap seam. The short real SIGTERM deadline and fake child startup remain deliberate OS integration; adapters own vendor-specific argv while this lower owner proves generic shell isolation, daemon secret exclusion and drain/termination.

`infra/frontmatter.test.ts` owns Markdown/YAML parsing/serialization preservation used by all vendors (Agent config §§4.1, 4.5, §6). Fixed text/body/metadata examples catch BOM/CRLF/fence handling and malformed mapping loss; parser-library replacement remains valid. `infra/markdown-items.test.ts` owns tolerant native item discovery, support-file enumeration without following links and refusal to overwrite bad skill metadata. The production adapters/preparers consume these helpers, while their broader fixtures do not cover all malformed/root/nesting variants here.

`infra/hash.test.ts` protects the persisted hook-ID format from Agent config §4.3 using a literal independent SHA vector and identity equivalence/difference examples; higher layers otherwise derive IDs through the same helper. `infra/names.test.ts` protects the final path-segment validation boundary shared by backups/stash/write owners (Agent config §4.5); it checks the error code, not incidental message wording. `infra/secret-digest.test.ts` protects the host-only revision representation's recursive redaction across every supported native spelling; individual adapter snapshots cannot cover nested OpenCode/Grok/Codex credential structures collectively. Each checks exported production helpers with non-test consumers, independent literal values and observable stable results; identifier/internal algorithm refactors preserving these contracts remain valid.

## Removed or narrowed support

Repository-wide caller searches found no production imports of the four dropped-key maps or `grokProfileConfig` outside their own module/barrel; they are now internal. Production still uses the same maps/builder with unchanged logic. The README no longer calls those maps exported. The private Claude read cap export also had only a test consumer and is now internal. The fake Grok `FAKE_GROK_REPORT` override became unused when normalization moved to the parser boundary and was removed. `runAgentCli.maxOutputBytes` had no production callers and was removed; the fixed production cap remains 4 MiB. `killGraceMs` remains because real Git clone cleanup selects a 500 ms grace. No native fixtures, recorded protocol captures, dependencies or package configuration became orphaned, and no production runtime behavior was changed.

## Validation and performance

Implemented test LOC: 10,075 → 9,986 (−89). Source/support changes: 101 insertions, 200 deletions across the 18 owned source/test/support files, before the audit report itself. No test files were added.

The initial full-run baseline log observed the following named costs with the repository default of four test files per package: Grok skill/command lifecycle 4,571.312036 ms; ZIP default caps 3,163.464274 ms; Grok plugin lifecycle 2,947.906670 ms; CLI SIGTERM-ignore 1,635.239322 ms. These motivated the process/setup optimizations; final equivalent measurements are pending central validation. The report does not infer an overall or CI speedup from them.

The first central `pnpm check:changed` run exposed an over-specific section-order expectation in the consolidated E2E case (display alpha-2/alpha-4/alpha-3 versus expected alpha-2/alpha-3/alpha-4). Source review confirmed that display follows scan order while naming follows picks. The case now compares the filename set, checks every card-to-file text mapping and independently verifies the requested two/one source bodies land at alpha-3/alpha-4. No production behavior was changed; repeat validation is pending.

Validation is scheduled centrally by the root agent to honor one test run per worktree. See the integrated repository report for exact commands/results and comparable full-suite wall-clock measurements. Per-case measurements and repeated focused optimization checks will be recorded here when available; source-based cost reductions are not themselves measured speedups. Intended retained expensive owners are the native CLI/RPC subprocess boundaries, real Git clone, real filesystem locks/watchers, shared-storage recovery and critical approval/secret workflows. None accesses a live daemon or real account home.
