# Agent-chat service and host supervisor cleanup

Completed cleanup; the pre-edit decisions below were recorded before changing tests or production seams. Original scope: 94 named tests in two files.

## Independent contracts and six-bar justification

Each retained row references the following six-bar record: (1) independent source; (2) real failure; (3) independent expected values; (4) stable seam; (5) refactor tolerance; (6) lowest owner/no stronger duplicate. The case name gives the distinct input and failure.

**C.** Chat GUI spec §3.1/§3.4/§6.1 and workflows spec §5.10 define launch identities, trust confinement, validated resume and owner persistence. Failure loses settings, grants arbitrary trust, launches wrong identity, or loses workflow ownership. Tests observe public create/switch responses, actual host HTTP payloads, and persisted records/files. Expected codes/paths/owner values are literal inputs required by those contracts, not owner calculations. Refactoring service internals leaves these seams intact. No lower owner covers daemon-to-host composition/record coordination; pure config validation remains in config tests.

**R.** Chat GUI spec §3.2/§4.6.4 and the documented CLI-update regression require notifying a surviving host when a CLI changes. Failure leaves stale model/auth capabilities after update. Public registry-change events produce real host refresh requests; literal adapter IDs and update sequences are independent. No private map/queue assertions; refactoring composition preserves outcomes. Host snapshot tests own probing after notification, not this daemon notification boundary.

**G.** Agent goals design §5.7 specifies lease renewal, old-host 404 compatibility, nonblocking boot, and legacy session handover. Failure strands a deploy or interrupts/forgets a continuing goal. Public supervisor triggers produce host-protocol requests/state; service tests own real HTTP route/auth decoding, supervisor tests own policy. Literal thread IDs, statuses, ordered stop/resume effects and external response cases can disagree with implementation. They tolerate internal rewrites and avoid duplicate host-side goal state tests, which own a different process.

**U.** The public binary upload API (`packages/api/src/index.ts`, MAX_UPLOAD_BYTES), chat GUI spec §6.3 transport rules, and stream lifecycle regressions require 500 MiB enforcement at the daemon transport, typed caller refusals, preserved source ownership, and closing abandoned upstream sockets. Failure crashes daemon, reports retryable outage for oversized data, leaks sockets, or corrupts upload. Tests use real streams, host HTTP, daemon HTTP or MCP public seam as appropriate. Literal status/error code/bytes and socket completion events are independent. Internal transforms/client calls can change. Daemon HTTP and MCP are separate error adapters; low-level duplicate transform tests are removed. Lowest ownership for each remaining transport/lifecycle contract.

**S.** Chat GUI spec §3.1/§8 defines authenticated adoption, foreign-process safety, drained code/protocol handover, readiness and protected PIDs; credible busy-host/late-ready/spawn-failure regressions supplement it. Failure kills live turns/foreign processes, leaves daemon unavailable or crashes it. Public supervisor methods expose state and stable OS/process/host adapter effects used by AgentChatService. Expected literal states, identities and ordered lifecycle effects are independent. No assertion on private methods/maps or loader shape; refactors preserve behavior. Host orchestration tests cannot protect daemon process supervision, so this is the lowest owner.

**L.** Agent goals design §5.7 legacy handover defines Codex-only consecutive provider-started turns, 3-second continuation gap, no user requests, and 45-second safe stopping window. Failure stops a user turn or never drains old hosts. legacyGoalTurnOf is a genuine module seam called by service.ts to parse another-version protocol data; tests use literal wire records and independently specified true/false classifications, tolerate parser rewrites, and uniquely cover malformed/ambiguous old-host payloads before supervisor policy.

**E.** Chat GUI spec §3.1/§8 explicitly limits inherited host environment. Failure leaks daemon secrets or prevents CLI resolution. buildAgentHostEnv has a non-test service caller and returns the actual spawn environment. Literal required paths and a seeded forbidden secret form an independent oracle. Internal object construction may change. This pure boundary is the lowest owner; no stronger host spawn test validates daemon secret isolation.

Isolated parser failure modes before retention: malformed snapshot mistaken for a runnable goal; wrong provider; missing/unknown running turn; user-originated current or prior turn; old continuation gap; absent prior completion; pending approval/question; malformed envelope. Environment builder failures: required host paths omitted, optional paths invented, daemon secrets inherited.

## Seam callers, removal risk and validation plan

Production calls AgentChatService from daemon index.ts; AgentChatService calls AgentHostSupervisor and buildAgentHostEnv/legacyGoalTurnOf; workflows agent/families.ts also calls proxyAccountFamily, so it stays exported. Service helper exports resolveHomeKind/isUsableConversationId/countingLimit, provider debounce constant, supervisor implementation constants, hostHasWork/drainBlockers, path/deadline overrides, and service nodeBin/mainPath/spawnDirect/now/sleep/uploadLimitBytes options have no non-test consumers beyond their owning implementations. Remove these exports/options while retaining unchanged defaults; supervisor process/clock adapters remain real service wiring. Both test-only drain methods were subsequently removed under the strict user requirement. Service tests now use real host request events and existing provider-changed broadcasts; supervisor tests drain settled harness promises with setImmediate. Service client/supervisor/summary and refreshProvider are private. relayedUploadClosesConnection has one production call inside index.ts; privatize its export after replacing private tests with the actual route.

Risk: accidental stream teardown or process lifecycle change is high, so only remove optional branches never used in production and preserve real wire/socket outcomes. Tests run without starting a daemon/agent host: temporary Unix-socket fake host and inject/temporary HTTP app only. Focused command: `cd apps/daemon && node --import tsx --import ../../scripts/test/assert-ok.mjs --import ./test/quiet-mock-timers.mjs --test src/agent-chat/service.test.ts src/agent-chat/supervisor.test.ts`. Root owns repository gates.
