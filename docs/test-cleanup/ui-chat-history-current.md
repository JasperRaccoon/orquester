## Independent sources and seam ownership

The [indexed-history design](../superpowers/specs/2026-09-23-thread-index-and-lazy-boot-design.md), especially History page and Client, specifies cursor paging, snapshot resets, whole-history projection, ordinal rewind eligibility, 25-page reveal limit and five-page load batching. The [fold-performance design](../superpowers/specs/2026-09-23-fold-performance-design.md), Client history bridge, specifies contiguous pages/bridge/window, first-position/latest-content merging, child exclusion, pending-request bridging, the inclusive 20,000-item cap, guarded resnapshot, stale-cursor omission and rewind invalidation. Shared `@orquester/api/agent-chat` history wire types define nullable/optional bounds and page boundary fields; AGENTS.md requires validating bridge payloads and tolerating data written by other app versions. The [goal specification](../superpowers/specs/2026-09-24-agent-goals-design.md) §8.4 assigns goal landmarks to turns. Persisted streaming and older Claude re-emission fixtures describe credible killed-host / old-log regressions. These are behavior sources independent of implementation bodies; constants imported from the fold only size fixtures to provoke eviction and never manufacture expected history output.

Production callers: `store.ts` consumes bounds/cursor/cap/collection/live-split/history projection and reveal functions; `reducer.logic.ts` applies snapshot/event/revert history updates; `AgentChatView.tsx` invokes load-older, `components/command-palette/reveal-turn.ts` invokes reveal, and the timeline consumes public rows/reveal/error state. `windowHasDropped` feeds public dropped-window presentation. No audited helper exists only for tests. The transport fake only delivers provided API frames/pages and records requests; it does not implement paging, projection, retention, rewind or reveal behavior.

## Six-bar justification for each retained or rewritten case

Each KEEP/REWRITE row below supplies its exact independent behavioral rule and recognizable failure, satisfying bars 1–2. Bar 3: expected values are literal wire cursors, supplied message/work IDs or content, explicitly documented budgets, or conservation/ordering of separately constructed log fixtures; none invokes the history implementation to calculate its own expected result. Bar 4: logic tests call the production history transformation seam with wire/fold data and inspect its contract outputs; store tests use public actions, incoming protocol frames, public outgoing requests and caller-consumed state. Bar 5: no source greps, class/markup snapshots, private call sequencing or synthetic chrome identifiers survive the rewrites; identifier-only internal refactors leave the data/protocol assertions intact. Bar 6: the logic cases isolate distinct merge/ownership/boundary rules at their lowest stable owner; store cases test async ordering, cache lifecycle or actual projection/provider wiring unavailable to a pure rule test. Each row explains the additional failure not caught by adjacent coverage; duplicated state-only cases are DELETE. Numeric memory/request budgets are specified resource/protocol contracts, not appearance counts.

Risk: removing duplicates is low risk with the stronger owners named per row. Retained cases protect data loss, stale rewind actions and navigation races, so those scenarios remain. Rewrites remove only chrome/copy/private-index assertions or close a missing-output false positive. No production behavior change is planned.
