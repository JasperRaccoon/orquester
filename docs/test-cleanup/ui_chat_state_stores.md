# Completed cleanup: agent-chat store, history and transport tests

Disposition ledger recorded before source edits. Scope: every named test in the seven files below. Parameterized loops are retained/deleted as part of their named case. This is implementation work, with results appended after verification.

## Independent contracts and six-bar records

Each KEEP/REWRITE row references one of these records **and its concrete named scenario**. Its name states the expected result/failure trigger; it is not inferred from the production result. The shared record supplies all six bar items, caller analysis and validation. DELETE rows explain why no distinct real behavior becomes unprotected and identify remaining coverage.

- **S (store actions):** B1: GUI design `docs/superpowers/specs/2026-09-21-agent-chat-gui-design.md` §§3.4, 6.2, 6.6, 7.2–7.6 specifies command identity, nonoptimistic log ownership, queue delivery/return, rewind acknowledgement, drafts and thread-local UI state; `2026-09-24-agent-goals-design.md` §8 specifies goal data. B2: the case's expected command/data/state becomes wrong to the composer/timeline (lost or duplicate send, stuck control, lost draft or wrong transcript). B3: literal fixture inputs and expected command IDs/text/attachment refs are independent of the implementation; no expected reducer output is computed by production code. B4: `createThreadStore`/registry and `actions`/published state are the owner seam used by `hooks.ts`, `AgentChatPanel.tsx` and composer. B5: assertions concern command protocol and observable state, not algorithm, private cache or collaborator call sequence. B6: action orchestration is the lowest seam that owns command timing and state handoff; leaf queue/draft/fold tests do not execute these operations or their stream/storage race. Risk: medium if removed; retained here without equivalent stronger owner. Tests mock transport responses, not command/state behavior.
- **L (reload/storage):** B1: GUI §7.4 and the persisted `composer-outbox.ts` v1 record contract require retaining pending/queued messages, replay under original command IDs, stale recovery and absence hold. B2: concrete scenario would lose, duplicate, reorder or silently dispatch user text/files, or strand Sending. B3: literal persisted v1 fixtures or an actual prior page's saved state are checked against prescribed order/IDs; fake receipt/delivery logic is removed. B4: store actions, tab storage and registered composer return protocol are used by real composer hooks and reload lifecycle. B5: only final public queue/draft/outgoing commands and browser lifecycle are asserted. B6: store is the lowest owner for outbox adoption plus live generation/transport coordination; standalone outbox parsing tests cannot observe these races. Risk: medium/high lost user work; no stronger owner for each distinct lifecycle described.
- **H (history merge):** B1: `2026-09-23-thread-index-and-lazy-boot-design.md` §C and `2026-09-23-fold-performance-design.md` Client/history bridge specify no missing/duplicate/reordered rows, newest payloads, turn-aware rewind gating and 20,000-row bounded memory. B2: case exposes missing/wrong message/tool state, wrong rewind target, unreachable search turn or stale rows. B3: literal row IDs/payloads/ordinals and the documented cap determine expectations; cache identity and production-generated reference projections are pruned. B4: retained validators and history projection/state functions are the production owner seams called by `store.ts`/`reducer.logic.ts`; their outputs directly feed published rows/actions. B5: no assertions on private encoded keys, memo identity or projection internals remain. B6: unique boundary combinations live at the history owner; cases duplicated by store action scenarios are removed. Risk: medium retained boundary corruption; no stronger retained owner for each remaining specialized input.
- **I (history operations):** B1: same two history specifications as H require loading/reveal, cursor continuity, snapshot invalidation and live-stream resync. B2: named scenario yields lost/duplicated transcript content, wrong navigation, dead spinner, stale rollback or an unnecessary/incorrect request. B3: host pages and expected visible IDs/cursors/state are supplied independently. B4: store public `loadOlderHistory`/`revealTurn`/`rewindTo`, stream and published rows are consumed by timeline and command palette. B5: tests permit alternate cache/layout algorithms; private cache reads and production-generated expected projections are removed. B6: the store alone coordinates asynchronous stream/page/lifecycle races; helper duplicates are deleted. Risk: medium; no stronger end-to-end owner of these precise races.
- **T (transport protocol):** B1: `packages/api/src/agent-chat/wire.ts` routes, stream frame types/output window contracts and GUI §§6.2–6.6 define bytes/routes/cursor/errors; §7.4 plus AttachmentRef defines attachment metadata/binary boundary. B2: wrong request path/cursor/code/decoded data prevents real daemon interop, duplicates events or corrupts tool output/files. B3: fixed route bytes, independent NDJSON frames and exact supplied error/output data can disagree with client mapping; malformed-window cases assert failure at the offending page. B4: `AgentChatTransport` and `Transporter` are the cross-runtime API used by both web and desktop; `attachmentRefFromUpload` also has the real `PickComposeSheet.tsx` caller. B5: checks target protocol data and public lifecycle, not request-builder internals. B6: transport owns wire mapping/window joins; server tests cannot verify this client implementation, and redundant line-parser cases are removed in favor of stream.logic. Risk: medium/high protocol incompatibility; no stronger client owner per retained operation.

Isolated history/transport units can fail by accepting malformed persisted/wire fields, merging overlapping IDs with stale data, losing lifecycle closure across page boundaries, using wrong turn ownership/ordinal for rewind/reveal, forgetting eviction indications, exceeding documented memory bounds, corrupting NDJSON sequence/cursor handling, or concatenating invalid output windows. Only named cases detecting these failures survive. Cache/object identity and private key formats are not unit failure contracts.
