# Agent-host goal cleanup: completed cleanup

This ledger was recorded before editing the three assigned suites. Original scope: 128 cases (63 goals, 61 hold, 4 legacy handover). Dispositions: **1 DELETE / 19 REWRITE / 108 KEEP**; 127 cases remain. There are no production behavior changes.

## Evidence and boundaries

Read the root AGENTS.md, README.md, daemon package.json and agent-host module README; each original case; the goal/hold/reconcile/identity/Stop/compaction paths in `orchestration/orchestrator.ts`; `adapter.ts`; the watchdog; `agent-chat/supervisor.ts:legacyGoalTurnOf`; and the direct legacy-reader test matrix. The independent requirements are [the accepted goal spec](../superpowers/specs/2026-09-24-agent-goals-design.md), including its explicitly recorded race amendments, and the public adapter/host/storage contracts. The spec’s concrete behavior is checked against the current wire contracts before relying on its historical implementation notes.

Production callers: `agent-host/server/http-server.ts` calls public Orchestrator commands, summaries, readThread, holdContinuingGoals and resumeGoalSessionsAfterHandover. The daemon supervisor calls the hold/resume endpoints; `agent-chat/service.ts` consumes legacyGoalTurnOf. GoalCommandOptions and StartSessionInput are the real adapter boundary used by Codex, not test injection exports. Event logs and durable head markers are storage contracts. No affected seam lacks a production caller; no production seam is removed here.
