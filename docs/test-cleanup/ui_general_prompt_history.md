# Prompt-history test cleanup

Status: completed cleanup. Dispositions below were recorded before edits; focused validation passed. Scope is the five named suites in `packages/ui/src/lib/prompt-history`. Every existing named case is listed in original order.

## Isolated owner failure modes

- Prompt derivation: lose/double list overlap, leak subagent/internal rows, assign wrong rewind turn, preserve stale index entries, or omit valid search matches.
- Index cache: repeat concurrent fetches, lose loaded data on failure, fail to recover from transient index state, fetch endlessly after exhaustion/failure, confuse empty bounded pages with exhausted history, or leak prompt text between sessions.
- Checkpoint derivation: expose unavailable diffs, let stale pages override live state, associate steers/autonomous turns with the wrong checkpoint, misreport file totals, or select the wrong rewind opener.
- Rewind action: bypass capability/busy gates, miss a compaction outside the visible window, use guessed counts, race a late request/send, or report success after failure.
- History selector: invalidate subscribers for token-only changes or fail to invalidate for changed busy state.

## Full six-part retention bar

### Contract P

1. Wire ThreadPromptEntry/ThreadPromptsResponse in packages/api/src/agent-chat/wire.ts; public recallablePromptText rules; rewind numbering in GUI design §7.4; concrete duplicate/stale-prompt and search failures documented in each case.
2. History list/search output consumed by prompt-history/hooks.ts and right-rail/history/PromptHistoryPanel.tsx.
3. Literal message IDs, text, ordinals and query results; no expected result is calculated by the production implementation.
4. createLoadedPromptsMemo/mergeHistoryPrompts/filterPromptsBySearch are the production derivation boundary; REWRITE moves private-map/wrapper and identity checks here.
5. Assertions concern selected data and search results, permitting different collections, caching and traversal algorithms.
6. API prompt/turn tests own normalization/dedup primitives; only client source joining, claim application, indexing and search semantics are retained here. Render checks do not own these rules.

### Contract I

1. ThreadPromptsResponse indexed/catchingUp/before and ThreadPromptTextResponse contracts in packages/api/src/agent-chat/wire.ts; API failure/retry semantics and concrete concurrent/short-page regressions recorded below.
2. Observable cache loading/ready/failed/fallback state, fetched prompt data and extra/missing requests affect visible history and retry controls.
3. Fixture responses and literal status/IDs/cursors determine expectations; fetcher mocks return transport data only, never implement caching or paging policy.
4. PromptIndexCache get/text/ensure/retry/loadOlder and the search/fill policy consumed by hooks.ts are the lowest client owners.
5. No exact copy, private timer collaborator, retry-count or copied hook-loop assertions survive; equivalent cache implementation remains valid.
6. Daemon index tests own server paging; they cannot catch browser cache loss/coalescing/fallback. Policy helpers are tested once; the duplicate simulated pager is deleted.

### Contract C

1. Checkpoint status/turnId/files in packages/api/src/agent-chat/thread.ts, conversation rewind numbering in GUI design §7.4, and concrete wrong-checkpoint/false-diff failures described below.
2. Wrong checkpoint, unusable diff, incorrect totals, wrong opener or missing search match is visible through PromptCard/CheckpointCard consumers.
3. Fixture turn/message IDs and literal summary totals/origin categories are independent expected data, not production-derived expectations.
4. checkpoints.logic functions are production owner seams called by hooks.ts, PromptCard.tsx and CheckpointCard.tsx.
5. Checks inspect semantic IDs/origins/totals, permitting key format, rendering, storage and traversal refactors.
6. Fold tests own checkpoint persistence; these cases uniquely own client joining, origin selection, totals and combined search. Duplicate summary/key assertions are removed.

### Contract R

1. GUI design §7.4 conversation-only rollback and capability/busy gates; wire rewindable/turnOrdinal; credible late-busy, compaction and unloaded-row safety regressions described per case.
2. Wrong/missing destructive rewind request or a wrong offer is directly caller-visible; mock rewindTo records the real action boundary.
3. Literal allowed/null targets, failure state and observed side-effect arguments; fixtures supply facts and never implement the action gating.
4. promptRewindTarget/latestLoadedCompactionAt/runPromptRewind are the panel action owners used by hooks.ts; rows derive their own verdict separately.
5. Checks preserve action/data semantics through refactors; private row shape and map memo assumptions are deleted.
6. rows.logic/history.logic and API compaction suites own primitive verdicts. These retained tests add panel-only source aggregation, provisional index offers and asynchronous action revalidation.

### Contract T

1. The separate production consumer useAgentChatThreadSelector in agent-chat/hooks.ts requires stable selected snapshots; GUI rewind busy gates require state changes to become visible.
2. Token-only updates must not trigger panel subscription changes, while a settled turn/request/rewind must immediately change command availability.
3. Two independently supplied thread states must produce identical snapshots only for unchanged selected facts; literal busy flags define real transitions.
4. createHistoryThreadSelector is the actual selector passed to the shared hook by prompt-history/hooks.ts.
5. The observer-facing snapshot stability contract survives changes to internal prompt/rewind caches, which are not separately asserted.
6. This is the outermost stable subscription owner. Private memo tests are deleted; primitive rewind tests do not verify whole-selector invalidation.
