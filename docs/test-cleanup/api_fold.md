# API fold, roster, turns cleanup

Status: completed cleanup. Decisions were recorded before edits; verification results are below. Every original named case in the assigned files is listed, including parameterized names.

## Independent contracts and six-part retention bar

For every KEEP/REWRITE below, the row names the exact input condition and required output; a violation is the failure the case detects. The following owner records explicitly supply the six bar items shared by those cases. Parameterized call closures are `tool.completed` and `tool.denied`; window cases are `parent` and `agent`.

- **Fold (F):** (1) agent-chat GUI design §§5.1, 5.4, 5.5, 6.3 and AGENTS.md require ordered per-thread replay, preserved resume identity, streamed messages, turn settlement, checkpoints, pending approvals, and rewind by started-turn order. (2) A wrong message, turn, prompt, checkpoint, approval, or resume identity is visible in snapshots/GUI/API. (3) Fixed event payloads and explicitly written expected IDs/statuses/text supply the oracle; reducer output never supplies expected fold behavior. (4) `foldThread`/`applyDomainEvent` and `toThreadSnapshot` are shared production interfaces. (5) Tests inspect resulting data, not caches, collaborator calls, or reference identity. (6) This is the lowest complete event-owner seam: parser tests cannot cover event ordering, request tombstones, retention interaction, or rewind. The matrix removes redundant turn-adoption/retention cases and reduce-vs-reduce checks. Production callers: daemon agent-host store and UI agent-chat reducer/history. Risk: low for deletions; no domain behavior changed.

- **Retention (R):** (1) fold-performance design §B and subagent-output-long-calls design require bounded parent/agent/message windows, retained unanswered questions/compaction markers/live openings, ranked live-work budgets, and lossless evicted rows for paged history. (2) Incorrect expiry loses timeline content, running work, unanswered questions or page continuity. (3) Named boundary inputs and explicit kept/dropped IDs/counts are the oracle; the copied reference implementation is removed. (4) Events enter the shared fold, outputs are fold state and public `itemsDroppedByRetention` consumed by UI history. (5) Cache counters/index object identity are removed. (6) No parser or UI test owns these cross-event retention decisions; distinct parent/agent/ceiling, closure, exemption, and eviction boundaries remain here. Production callers: fold commit, UI reducer/history retention bridge. Risk: low; boundaries remain protected.

- **Snapshot (S):** (1) AGENTS.md requires disposable validated snapshots with durable log authority; thread-index/lazy-boot design §A2 and GUI continuation/goals contracts define persisted markers. (2) Corrupt cache acceptance can lose messages/requests/resume state; rejecting valid state makes cold loads fail or discard needed markers. (3) A roundtrip must preserve its supplied input data (an identity property independent of the codec), and malformed fixtures must return null; tail rewrites assert fixed output values. (4) `serializeFoldState`, `deserializeFoldState`, `parseFoldSnapshotFile` are the actual storage boundary. (5) No private cache/identity/inventory assertion remains. (6) This codec owns field validation, optional legacy stamps, unknown provider payloads and version/thread/sequence gating; fold tests cannot catch codec loss. Production callers: agent-host store snapshot read/write. Risk: low; historical versions 2/3/4 remain rejected in the compact file validator table.

- **Roster (A):** (1) GUI design §7.6 and runtime task protocol specify stable task identity, terminal precedence, resumptions, field-wise usage, safe session URLs, liveness, workflow membership/counts, and retention ranking; named restart regression documents stable progress-row replacement before the previous completion. (2) Incorrect agent status, missing member, duplicate activation/token charge, dangerous URL, or lost task result is caller/GUI-visible. (3) Literal status/data/counts for supplied provider rows are independent expected results. (4) `foldSubagentActivities` and `deriveAgentPanelModel` are stable public read seams. (5) Engine shape/reference identity and sort implementation are not required. (6) These owner-level semantic cases supersede roster-engine parity/property/identity suites; fold-level liveness case only verifies session-event wiring. Production callers: fold, UI subagent panel and daemon leftover-work orchestration. Risk: low; semantic task regressions remain.

- **Turns (T):** (1) GUI design §§5.1, 5.5, 6.4 and MCP turn numbering contract specify settlement finality, pending-turn failure, positional latest turn and 1-based distinct started-turn ordinals. (2) Wrong state/duration or ordinal changes displayed status or reverts the wrong turn. (3) Literal timestamps/statuses/ordinals are independent of the helpers. (4) Public `applySessionStatusToTurn`, `deriveLatestTurn`, `startedTurns`, `turnOrdinal` supply the smallest stable data seam. (5) Retained cases assert values; no reference reuse assertion remains. (6) Fold tests cover event integration; retained helper cases uniquely exercise pending failure, finality, empty latest summary, null/unrecognized IDs, duplicates, and ordinals. Production callers: fold, daemon indexer/checkpoint commands/MCP, GUI prompt history. Risk: low.

Isolated-unit failure modes considered before retaining: T can settle twice, miss a pending failure, pick chronological instead of positional latest, count pending/duplicate IDs, or use zero-based numbering. A can lose task state on partial/out-of-order rows, confuse relaunch and replay, double count usage, admit unsafe links, misclassify liveness or hide workflow members. S can lose input fields, accept malformed/cross-thread/stale-version data, or restore a state whose next event duplicates/forgets data. Retained cases below correspond to those visible failures.
