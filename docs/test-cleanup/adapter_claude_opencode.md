# Claude, OpenCode, and shared adapter test cleanup

Completed cleanup, not audit-only. The before-edit inventory contains 797 named definitions across 29 files (parameterized families are listed once). Dispositions were recorded before editing and updated before subsequent pruning.

Sources: [GUI design](../superpowers/specs/2026-09-21-agent-chat-gui-design.md), [goals design](../superpowers/specs/2026-09-24-agent-goals-design.md), [Claude captures](../../apps/daemon/test/fixtures/claude/README.md), [OpenCode captures](../../apps/daemon/test/fixtures/opencode/README.md), and repository/host AGENTS rules. Current source and wire contracts were checked against those sources.

For every retained isolated unit, the possible failures were listed first: wrong protocol grammar, field/type/unit mapping; lost/duplicated or misowned output; wrong permission/account/model; wrong resume boundary; absent data confused with zero or logged-out state; lost transcript rows/goal verdict; stalled process/read or missing resource cancellation. The case names below identify each distinct input and expected failure.

The six retention checks are split into file-level contract records (independent requirement, seam, caller and lower-owner analysis) and per-case records (specific expected output). Their combination is the justification for each KEEP/REWRITE, not a claim that fixture presence or a type inventory is enough. Expected data comes from fixed provider/config inputs or literal public outcomes, never recomputed by the owner under test. Retained assertions tolerate identifier/decomposition changes because they observe the specified protocol/state/output seam.

Validation for every file: from `apps/daemon`, `node --import tsx --import ../../scripts/test/assert-ok.mjs --import ./test/quiet-mock-timers.mjs --test src/agent-host/adapters/<path>`. Risk: deleting a protocol oracle can hide the named visible failure; DELETE rows identify the stronger remaining owner or explain why no real behavior was asserted.
