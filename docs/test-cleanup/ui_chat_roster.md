## Independent contracts and full retention bar

Failure modes considered before retaining isolated units: shell payload loss/reordering, wrong task-vs-tool interpretation, stale cached output, changed disclosure identity, retention dropping the only full-output affordance; saved child state lost/cross-contaminated, stale middle position overriding follow, unbounded/incorrectly evicted memory; counts conflating agents with shell/loop/goal kinds; partition misclassifying kinds or reordering members.

- **SHELL (all REWRITE records):** (1) GUI design §7.6, lines 4550–4594, and MCP read-output contract specify shell-owned output, retained call identity, arrival-order data and retention behavior; Grok normalized task frames specify summary versus launch description. (2) Missing/wrong/stale command output or lost disclosure is a visible failure. (3) Expected command/output/id values are literal fixture input and protocol semantics, never another production invocation. (4) `projectBackgroundShell`, called by `AgentDrillIn`, is the lowest production projection seam; downstream joined output is observed only where the byte-joining boundary matters. (5) No private calls, memo identities or markup arrangement remain. (6) Generic row-chrome joining does not cover shell delta promotion/task interpretation; the one render check covers projection wiring only, not these edge cases. Risk low; validation A below.
- **MEMORY (all REWRITE records):** (1) GUI design §7.6 lines 4695–4703 explicitly requires per-agent state restoration, follow precedence and a 50-agent bound. (2) Reader position/disclosures lost or copied between agents, stale re-pin, or incorrect eviction is observable on reopen. (3) Explicit agent IDs, saved values and documented literal capacity are independent expected data. (4) `rememberDrillIn`/`recallDrillIn` are AgentChatView’s seam and `drillInOpening` is AgentDrillIn’s seam; the test-only composition wrapper will be removed. (5) Tests observe restored values, no object identity/implementation callbacks. (6) No lower owner covers this memory; lib drill-in tests own projection/liveness only. Risk low; validation A.
- **COUNTS (KEEP records):** (1) GUI design §7.6 kind-separated counts and API RuntimeSubagent kind/status contract require truthful separate counts. (2) Shells counted as workers or loops counted as shells misreport fleet state. (3) Literal independently counted input populations form expected values. (4) `rosterKindCounts` is used by AgentRoster and AgentChatView. (5) It asserts data, not formatting/layout/private calls. (6) Lower roster fold does not produce these UI kind counts; rendered count copies are deleted. Risk low; validation A.
- **PARTITION (KEEP records):** (1) GUI design §7.6 requires separate shell section and stable per-kind ordering; loop/goal API kinds are distinct from shell. (2) A loop under shells or swapped identities changes what the roster user reads. (3) Explicit fixture IDs define the expected partitions. (4) `partitionRosterRows` is AgentRoster’s section-selection seam. (5) No markup/classes/row geometry, only ordered member IDs. (6) Counts alone cannot prove membership/order and lower dock selector does not partition these sections. Risk low; validation A.
- **SEEDED OUTPUT (REWRITE check):** (1) GUI design §7.6 documents the credible second-projection regression: a seeded store caused AgentDrillIn’s shell projection to be discarded. (2) Opening a shell then hides its actual output. (3) Literal fixture command and output are expected rendered data. (4) AgentDrillIn rendered from the real store/stream is the lowest wiring seam reproducing this failure. (5) Assertions inspect user data only; no classes, generated IDs, row counts, wrapper shape or exact UI copy. (6) Projection tests cannot catch ChatTimeline ignoring that projection. Risk low; validation B.

## Production callers and planned dead support removal

`AgentDrillIn` calls the shell projection and disclosure seeder, callback mapping and opening calculation. `AgentChatView` calls memory remember/recall and roster counts; `AgentRoster` calls selection/counts/partition/labels; `AgentRosterRow` and `WorkflowGroup` call format/status helpers. Repository reference searches found no production calls to `backgroundShellEntries`, `backgroundShellRows`, `openDrillIn`, `expandedRosterLabel` or custom memory capacity. The shell rows and memory composition wrappers exist only for these tests. Selection `totalCount/liveCount/finishedCount/exempt`, the `ROSTER_COLLAPSED_ROWS` alias, `isLiveStatus`, and drill-in `agent`/`rows` overrides have no production consumers. Remove those dead surfaces without changing the production projection or selected row behavior. Shared AgentDrillInProps field removals coordinated with parent.
