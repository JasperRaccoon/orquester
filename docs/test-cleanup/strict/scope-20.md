## Six-bar review model

Every KEEP/REWRITE entry below maps to its file’s independent source and production seam. B1: that named requirement/protocol/storage/security contract supplies the behavior. B2: the named scenario describes the concrete caller-visible failure; assertion results are fixed fixture outputs, state, data, codes or actual persisted bytes. B3: expected fixtures/literals are supplied independently (round trips additionally assert fixed preserved fields), not copied from production computations. B4: the described service, protocol, filesystem, process or public pure-function seam is the observation boundary. B5: internal extraction/renaming/storage-write refactors preserve these outcomes; private collaborator-hook scenarios are deleted. B6: each retained scenario covers the distinct boundary stated in its title and suite ownership note; overlapping higher-layer scenarios are removed or narrowed.

Isolated-unit failure inventory: parser framing/encoding/bounds; priority inversions and timestamp/cursor errors; unauthorized identity/path/process scope; loss of persisted unknown fields; wrong HTTP/protocol bytes/status; process/stream teardown races. Only cases witnessing those outcomes survive.

Validation for each entry: from apps/daemon, `node --import tsx --import ../../scripts/test/assert-ok.mjs --import ./test/quiet-mock-timers.mjs --test --test-concurrency=2 <file-relative-to-apps/daemon>`. Scope runs use the same command over all assigned existing files. Root agent owns repository gates.
