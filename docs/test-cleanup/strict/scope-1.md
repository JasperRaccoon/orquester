For each KEEP/REWRITE, the six-bar justification is the combination of its file contract block and its named case/oracle. 1: independent source is named per file. 2: failure is the named scenario violating the listed caller-visible consequence. 3: oracle comes from authored test literals, fixture identity, format standards, or mathematical invariants, not a call to the implementation to compute the answer. 4: the production-used public seam is named. 5: assertions concern returned data, protocol bytes or persisted state, not source/import shape or private calls; changing algorithms while preserving that contract leaves them valid. 6: these are the lowest shared contract owners; consumer tests only add wiring/lifecycle coverage, with known duplicates removed by the owning agents. For REWRITE the removed assertion is excluded from this justification.

Isolated-seam failure inventory: parsers can accept malformed input, reject compatible old/new input, lose fields, or leak unsafe fields; folds can violate event ordering/identity, lose text, resurrect closed work, corrupt rewinds or discard live anchors; serializers can lose state or trust corrupt cache; expressions/rules can return wrong values/branches or expose forbidden data; graph/patch operations can run wrong paths or mutate only part of a batch; schedules can skip/duplicate calendar instants; published recipes can be unusable or operate on the wrong external record. Only corresponding output-based cases are retained.
