# Scope 12 — host orchestration cleanup

Pre-edit disposition recorded after reading every original test and its production owner. Implementation prunes nine redundant cases and rewrites ten cases to isolate their specified behavior. Original declarations are listed verbatim for reconciliation; repeated scenarios inside a declaration are described in its reason.

The independent requirement documents are `docs/superpowers/specs/2026-09-21-agent-chat-gui-design.md` and `docs/superpowers/specs/2026-09-24-agent-goals-design.md`, checked against current API/service contracts and production callers. A historical note alone was not grounds for retention.

Six-bar mapping for every KEEP/REWRITE below: **1** the file source plus named behavior supplies the independent requirement; **2** each row names the observable failure; **3** each literal result/input boundary, opaque supplied data, persisted state, or explicit absence is the oracle, never a production-generated expected value; **4** the file seam is a service/public protocol boundary or a pure decision consumed by a real caller; **5** assertions depend on outcomes/inputs of that contract and survive renamed helpers, reordered implementation and different internal containers; **6** each row identifies its distinct failing path, while duplicates listed DELETE move to the named stronger owner. Parser matrices remain at the lowest decoding seam; retained orchestration cases protect separate invocation/ordering/authority decisions rather than redoing those matrices.

Isolated-unit failure inventory: liveness can misclassify, resurrect, lose or indefinitely retain tasks, confuse provider wakes with host turns, or apply the wrong expiry; provider registry can serve missing/stale/foreign catalogs, launch overlapping/unneeded probes, lose runtime status updates or write after shutdown; parsers can intercept ordinary text, alter user data, accept malformed/unsafe payloads or reject valid protocol boundaries; session policy can restart unnecessarily, fail required restart or carry an incompatible cursor. Only cases detecting these specified failures survive.

Risk: low for removal of duplicate/inventory assertions; medium-value contracts (identity, resume, credentials, bounded reads) remain exercised at their listed stable boundaries. No production behavior is changed. Focused validation: from apps/daemon, `node --import tsx --import ../../scripts/test/assert-ok.mjs --import ./test/quiet-mock-timers.mjs --test --test-concurrency=2 src/agent-host/orchestration/{identity,item-reads,launch-config,liveness,provider-snapshots,session-binding,session-policy,slash,v1-residual,validate}.test.ts`. Root owns repository check/test gates.
