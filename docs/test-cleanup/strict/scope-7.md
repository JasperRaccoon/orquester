# Codex adapter strict test cleanup (scope 7)

Completed cleanup, not an audit-only proposal. This ledger was created before test edits; the validation result is appended after execution. Original declaration names and baseline lines are retained for reconciliation; table-driven declarations list their scenario domain below.

## Independent evidence and six-bar reading

- **C**: agent-chat GUI spec §4.5 Codex child-routing trap, §7.6 roster/call ownership; fixtures/codex/README.md observations 19–20, 22 and 24; generated ThreadItem/Turn protocol types. Failure modes are parent/child identity collision, parent state hijack, stale prompts attributed to a later run, permanently spinning calls, lost roster names/answers, or stale end records closing new work.
- **Q**: GUI spec §6.2 pending native questions and the observed child-question regression documented in the test: the parent finishing must not erase a child's still-answerable card. This is the sole host-through-provider workflow for that bug and writes a JSON evidence artifact.
- **O**: follow-ups adapters/output/composer/history plan Task 3, fixture observation 18, and public command-output/truncated storage contract. Dropping or cutting unmarked output makes read_tool_output falsely report incomplete data as complete.
- **G**: agent-goals design §6 and §6.2.1–5, §5.7 conditional handover resume, generated ThreadGoal. Wrong transition/status/counter, stale response resurrection, lost carry, incorrect throttle or malformed goal handling changes the user's goal or continuation control.
- **H**: GUI spec §4.5 native history and §7.3 replay, recorded fixture 07. A resumed conversation must preserve text, IDs, chronological order, historic status and avoid billing old usage or creating live work.
- **M**: GUI spec §4.3 decision table, §4.4 mode table, §3.2 version gate; fixture observations 2, 9 and initialization userAgent; generated approval/config types. Wrong values approve the wrong scope, retain unsafe mode, or reject supported providers.
- **P**: agent-host README process-liveness/deadline rule and the probe-child regression: a dead probe must resolve its error without waiting thirty seconds.
- **T**: fixture README transport observations 1, 15 and 16, GUI §4.5 NDJSON transport and §3.1 bounded pending requests, plus AGENTS.md unknown-frame warnings. Misrouting IDs, wedged parked approvals, missing refusal codes and promises surviving child exit are caller-visible failures.
- **R**: recorded redacted fixture frames and provenance in apps/daemon/test/fixtures/codex/README.md; GUI §4.2 normalized events; workflow design §5.4 structured account-failure reason. Expected captured text and IDs are independent provider data, not UI copy.
- **S**: GUI §4.1 adapter lifecycle, §4.3–5 Codex wire, §6.1 resume, §6.2 Stop/question behavior, §5.5 rollback; goals §6.2/§5.7 for goal cases; AGENTS.md secret redaction. Every retained case below names its distinct triggering sequence and resulting externally observed behavior.
- **U**: GUI §4.2 item/token/limit data, §4.6.8 native skill syntax, §4.6.4 snapshot preservation and bounded workspace cache, §4.1 one ordered adapter event stream. Fixture usage observation 6 is the independent cumulative-versus-last arithmetic source.

For each **KEEP**, bars 1–3 are the source code above, the named concrete failure/oracle below, and fixed input/expected literals (captured values for replay). Bars 4–5 are the file's stable seam below: assertions concern returned data, emitted event contracts, actual wire bytes or iterator outcomes, never source names/private call shape. Bar 6 is the stated distinct coverage owner: lower converters own conversion; the peer owns multiplexing/refusals; sessions own orchestration/order/child exits; history owns offline projection; only the critical child-question workflow reaches the host. Similar setups with different statuses, timing orders or ownership are independent failures, not duplicate replay at additional layers.

For each **REWRITE**, all six bars apply to the remaining behavior in its row. Removed assertions were incidental copy, opaque identifier spellings, private inventories or a negative assertion that could pass because an unrelated frame met it. No replacement behavior or production behavior is added. The retained goal-command response wording is explicitly specified by agent-goals §6.2.3; it is not incidental display copy. **DELETE** rows identify the surviving stronger owner or why there is no independently required failure.

Risk: low for deletion of duplicate/copy assertions; protocol regressions are retained. Removing assumptions about opaque IDs intentionally permits behavior-preserving ID refactors. No generated binding is modified.

Focused validation (cwd apps/daemon): `node --import tsx --import ../../scripts/test/assert-ok.mjs --import ./test/quiet-mock-timers.mjs --test --test-concurrency=2 src/agent-host/adapters/codex/*.test.ts`. Root agent owns full repository gates.
