# Disposition reconciliation

Independent review of all 45 flags produced by the disposition checker against the live worktree and `scope-1.md` through `scope-20.md`. No true stale DELETE, REWRITE or KEEP disposition was found in these flags. This is a reconciliation of recorded dispositions, not a new behavioral audit or a test run.

The checker uses substring matches across entire ledger rows, requires unchanged case titles in the same file, and compares cached per-case hashes. Those heuristics miss intentional renames, moves and shared-setup changes; they can also mistake a stronger-coverage cross-reference for a second disposition. The source and diff were read for every row below.

- 30 `REWRITE MISSING` flags: renamed or consolidated survivors.
- 7 `AMBIGUOUS DISPOSITION` flags: the exact KEEP row is unambiguous; other rows only mention the name as a substring or stronger-coverage reference.
- 5 `REWRITE BODY UNCHANGED` flags: the rewrite is in setup, a shared helper/fixture, or the enclosing parameter matrix.
- 3 `REWRITE BODY UNCHANGED` flags: the cached current inventory predates a completed body rewrite.

All paths below are repository-relative; original line numbers identify the baseline case, not its current location. Original scope ledgers remain authoritative for the six-bar rationale and validation results. No production or test code was edited and no tests were run during this reconciliation.
