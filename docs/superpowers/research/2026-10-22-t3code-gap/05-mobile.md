# 05 — Mobile experience: T3 Code native app vs Orquester PWA

Analyst scope: mobile navigation, native feel, push, offline and reconnect, composer and attachments, diff and terminal on a phone, LaTeX, store packaging, mobile performance. T3 paths are relative to `t3code_codebase/`; Orquester paths are relative to the repo root. "(new)" marks work that landed in T3 between e8d87689 and ed9b7ca9 (19–22 Oct 2026; 91 commits touch `apps/mobile`).

**How the two products are built.** T3 ships a separate Expo / React Native app (`apps/mobile`, about 1,088 TS files). It has 8 local native modules (`apps/mobile/modules/{t3-agent-notifications,t3-composer-editor,t3-native-controls,t3-review-diff,t3-source-text,t3-subscription-widget,t3-terminal,t3-widget-expiry}`), a forked react-native-screens (`docs/operations/mobile-screens-fork.md`), and a hosted push relay (`infra/relay`). Orquester ships one responsive React UI (`packages/ui`) as an installable PWA (`apps/web/public/site.webmanifest`, `apps/web/public/sw.js`). Web Push goes straight from the daemon (`apps/daemon/src/push.ts`).

## 2. They do it better

1. **The push loop is finished; ours stops before the tap.** In T3, an alert opens the exact thread, stays quiet if you are already looking at that thread, and batches several agents into one alert (`foregroundNotificationBehavior.ts`, `agentActivityAlerts.ts`). Our daemon picks good triggers (needs-input, finished, plan-ready, approval, agent `notify_user`, workflow run; `push.ts:225-330`), but tapping a chat alert drops you on whatever screen was last open (`sw.js:280-299`). The most common mobile action ("agent needs approval → tap → approve") costs us a manual hunt through the drawer.

2. **Navigation model.** T3's phone is a stack: Home (all threads across hosts) → Thread → Terminal/Review/Files. Everything in it is URL-addressable, back-swipeable, and animates the shared native header (`docs/internals/mobile-navigation.md`). Ours: hamburger drawer → project → tab switcher sheet → bottom section bar (`TopBar.tsx:40-80`, `MobileSections.tsx:1-23`). It is three levels with no Back integration outside workflows. The agent you care about lives in the drawer rather than on the first screen.

3. **Touch affordances on lists.** T3 rows have swipe actions with haptic confirmation (`thread-swipe-actions.tsx:1-80`) and native long-press menus. Ours depend on `contextmenu`, which iOS Safari never fires on long-press (`OpenedAgents.tsx:90`, also `WorkspaceProjects.tsx:67, 324`, `WorkspaceList.tsx:223`, `RepoGroupSection.tsx:173`). We already wrote a pointer-based long-press with `navigator.vibrate` (`components/workflows/phone/use-long-press.ts:30-70`), but only the workflow editor uses it.

4. **Keyboard handling in the composer.** T3 uses `react-native-keyboard-controller` (13 files) and fixed Android cases (new: `dc528938` composer lagging the keyboard / dropping under the nav bar, `dac3437d` composer stays one row until the draft wraps, `d6c67ceb` iOS text alignment at every Dynamic Type size). Our visual-viewport approach (`hooks/use-viewport-height.ts`, `hooks/use-soft-keyboard-open.ts`, `components/layout/AppWrapper.tsx:17`) is solid and well reasoned. A web page still cannot sync to the keyboard animation frame by frame, so this item is closer than the others.

5. **Terminal ergonomics.** Both have a key bar. T3's adapts to the host OS (cmd vs alt), latches modifiers, and adds the symbols phone keyboards hide (`ThreadTerminalRouteScreen.tsx:556-585`). It also renders with libghostty natively (`modules/t3-terminal/README.md`). Ours is xterm.js with good one-finger TUI scrolling (`TerminalView.tsx:341-447`) but a fixed key set.

6. **Diff reading on a phone.** T3 highlights with Shiki and marks word-level changes (`reviewWordDiffs.ts:116-189`). It caps huge payloads (new: `6fc3c9ee`) and lets you turn selected lines into a comment for the agent (`ReviewCommentComposerSheet.tsx`). Ours is monospace +/- only (`components/git/DiffView.tsx:1-45`).

7. **Performance discipline.** T3 has a render-counter harness that drives a real provider turn and measures renders mid-stream (`docs/internals/mobile-development.md` "Measuring renders", `apps/mobile/scripts/measure-renders.mts`). A test keeps React Compiler bailouts shrinking (`apps/mobile/src/reactCompilerCoverage.test.ts`). It virtualizes with LegendList (10 screens) and recently cut per-chunk JS about 8x on long threads (new: `cf558963`, `71b86708`). Our timeline is deliberately unvirtualized with `content-visibility: auto` (`components/agent-chat/timeline/ChatTimeline.tsx:56-61`, `styles/agent-chat.css:748-754`) and memoised rows. That is reasonable, but we have no mobile measurement harness to confirm it holds on a mid-range Android phone.

## 3. Worth copying (ranked by value ÷ effort)

1. **Session deep link from push (S, H).** Fixes a real bug.
   - Port: in `apps/web/public/sw.js` `notificationclick`, read `data.sessionId` (validate it like `isLinkId`). Post `{type:"orquester:open-session", sessionId}` to a focused client, or `openWindow("/?session=<id>")`.
   - Add `lib/sessions/deep-link.ts` next to `packages/ui/src/lib/workflows/deep-link.ts`, with the same parse/strip/request trio. It resolves through `focusAgentSession` (`components/attention/agent-sessions.ts:173`).
   - Wire it in `apps/web/src/pwa.ts` and `apps/web/src/main.tsx`.
   - Crib from: `apps/mobile/src/features/agent-awareness/notificationNavigation.ts` and `notificationPayload.ts` (allowlist parsing).

2. **Back-button integration for every phone overlay (S, H).** Generalize `components/workflows/phone/back-close.ts` into `packages/ui/src/hooks/use-back-close.ts` and call it from `BottomSheet` (`components/ui/sheet.tsx`), the mobile drawer (`components/sidebar/Sidebar.tsx`), `MobileSectionView` (`right-rail/MobileSections.tsx`) and `Modal`. No T3 code needed. Their rule to copy is "Back from a child returns to its parent" (`c5f536cc`).

3. **Foreground suppression and stale-completion guard in the SW (S, M).**
   - In `sw.js`'s `push` handler, `clients.matchAll({type:"window"})`. If a visible client reports (via a `postMessage`/`clients` focus check) that it is showing `sessionId`, skip `showNotification`. Web Push needs a user-visible notification, so on Chrome show a silent `tag`-replacing one rather than none.
   - Add a `sentAt` to the payload in `apps/daemon/src/push.ts` and drop alerts older than 2 min.
   - Crib from: `foregroundNotificationBehavior.ts` and `agentActivityAlerts.ts:16` (`isFreshTerminalNotification`).

4. **Long-press menus that work on iOS, plus swipe actions on agent cards (M, H).**
   - Move `components/workflows/phone/use-long-press.ts` to `packages/ui/src/hooks/` and use it in `OpenedAgents.tsx`, `WorkspaceProjects.tsx`, `WorkspaceList.tsx` and `RepoGroupSection.tsx`.
   - Give `AgentCard` a pointer-driven horizontal swipe exposing Archive/Close and Mark unread, with an undo toast through `components/status/ToastStack.tsx`.
   - Crib interaction constants and the "one open row at a time" rule from `apps/mobile/src/features/home/thread-swipe-actions.tsx` (`THREAD_SWIPE_SPRING`, `ACTION_ITEM_WIDTH`) and `HomeScreen.tsx:264-316`.
   - Later: let a phone with no project open land on "Opened agents" as its main view (`components/main/MainView.tsx`) instead of "Select a project".

5. **Sticky modifier keys in `MobileKeyBar` (S, M).** Add a latched Ctrl/Alt state that transforms the next byte (Ctrl: `c & 0x1f`; Alt: `\x1b` prefix) in `components/terminal/MobileKeyBar.tsx`, plus `~ | / -` keys. The host OS is known daemon-side if we want cmd/alt labels. Crib from `ThreadTerminalRouteScreen.tsx:556-585` and `apps/mobile/src/features/terminal/terminalInput.ts`.

6. **Photo downscale + camera/photo affordance in the composer (S, M).**
   - In `components/agent-chat/composer/ChatComposer.tsx` `stageFiles`, resize `image/*` files above a dimension cap with `createImageBitmap` + `OffscreenCanvas.convertToBlob({type:"image/jpeg", quality:0.85})` before upload.
   - Add `accept` hints and a "Take photo" item (`capture="environment"`) to the attach button on phones.
   - Crib the size policy from `packages/client-runtime/src/imageAttachmentSize.ts` (imported by `apps/mobile/src/lib/composerImageFit.ts`).

7. **Swipe-to-dismiss and two-height detents for `BottomSheet` (S, M).** Pointer handlers on the grab handle in `components/ui/sheet.tsx`: drag down past ~30 % closes, drag up expands from 75vh to 92vh. Mirror T3's detent pairs `[0.75, 0.92]` / `[0.6, 0.92]` (`Stack.tsx:738-772`).

8. **Durable outbox for phones (M, M).** Move the composer outbox from `sessionStorage` to IndexedDB, keyed per tab-session plus a device-wide "unclaimed" bucket, in `components/agent-chat/composer/composer-outbox.ts`. Hold sends while `connection === "reconnecting"` instead of giving up at about 1¾ min; replay under the same `commandId` (receipts already dedupe). Background Sync can flush on Android Chrome. Crib from `apps/mobile/src/state/thread-outbox-{manager,storage}.ts` (atomic writes, `flushThreadOutboxWrites`).

Cheap PWA extras (all S, mostly Android): manifest `shortcuts` ("New chat", "Attention"); `navigator.setAppBadge(count)` driven by the attention count already computed in `OpenedAgents.tsx` (`summarizeAgentSessions`), which works on iOS 16.4+ installed PWAs too; a QR code of the remote URL in desktop Settings → Remote access; `share_target` routed to a new-chat draft.

## 4. We do it better / they lack

- **Push without a hosted relay or account.** Our daemon signs VAPID pushes itself (`apps/daemon/src/push.ts`, key at 0600, never returned). It works over a direct or Tailscale connection, with SSRF-guarded endpoints (`isValidPushEndpoint`). T3 needs T3 Connect, a Clerk sign-in and a Cloudflare relay with FCM/APNs secrets. Its docs say: "a direct or Tailscale connection alone does not enable push notifications" (`docs/user/mobile-notifications.md`; setup in `docs/operations/android-notifications.md`).
- **More push sources.** Approval-card pushes (`notifyApprovalNeeded`), plan-ready, agent-initiated `notify_user` with per-chat and per-credential rate limits (`push.ts:36-48, 270-296`), and workflow-run pushes with a working deep link. T3 alerts cover finished, failed, approval and input.
- **Zero-install, same-code parity.** The phone gets the desktop UI's features the day they ship: workflow phone editor with long-press, sheets, Back and key bar (`components/workflows/phone/*`); browser tab with touch forwarding and pinch (`components/browser/BrowserView.tsx:166-181`); remote desktop; files; git tab. T3's separate mobile codebase keeps chasing web: new commits `f16251f1` "bring model controls in line with web", `cdaaa742` / `ecfe4f79` "chat chips match desktop", `0dc38c75` "add project and checkout removal".
- **Reconnect after sleep.** One debounced wake on `visibilitychange`/`resume`/`pageshow`/`focus`/`online` (`packages/ui/src/OrquesterApp.tsx:74-97`), plus a half-dead-socket ping probe. This matches T3's `app-state-wakeups.ts` (10 s probe vs reconnect) in effect.
- **Service worker cache** that never evicts the shell's own chunks and bypasses auth and stream routes (`apps/web/public/sw.js:1-30, 95-135`). T3's web app has a manifest but no service worker or web push (`apps/web/public/manifest.webmanifest`, no `serviceWorker` in `apps/web/src`).
- **Terminal on a phone for agent TUIs.** One-finger scroll inside full-screen TUIs that also blocks pull-to-refresh (`TerminalView.tsx:341-447`), and clipboard images pasted straight into the PTY session as uploaded files (`MobileKeyBar.tsx:35-70`). T3's terminal is shell-oriented; its agent UI is chat only.
- **LaTeX: parity.** T3's "LaTeX on mobile" (new: `cb0553ea`) catches up to what our shared chat markdown already renders with KaTeX (`components/agent-chat/timeline/markdown/math.ts`, `ChatMarkdown.tsx`; KaTeX chunks budgeted in `sw.js:21-23`).

## Appendix: what a PWA can match, and what needs native

| Capability | PWA reality (2026) | Verdict |
|---|---|---|
| Push alerts, tap to open thread, grouping, foreground suppression | Android: any browser. iOS 16.4+: installed PWA only. The SW decides what to show. | **Match** (items 1, 3) |
| App icon badge | Badging API: Chrome Android, iOS 16.4+ installed PWA | **Match** |
| Back gesture / hardware Back | `history` entries + `popstate` (pattern already in `back-close.ts`) | **Match** (item 2) |
| Swipe rows, drag sheets, long-press menus | Pointer events + CSS transforms | **Match** (items 4, 7) |
| Haptics | `navigator.vibrate` on Android only; nothing reliable on iOS | Partial |
| Keyboard-synced composer | `visualViewport` (done); VirtualKeyboard API on Chrome only | Mostly matched already |
| Camera / photos / downscale | `<input capture>`, `createImageBitmap`, `OffscreenCanvas` | **Match** (item 6) |
| Dictation | OS keyboard mic works; Web Speech API is optional | Effectively matched |
| Offline outbox + cached threads | IndexedDB; Background Sync on Chrome only | **Mostly match** (item 8) |
| Share-into-app, launcher shortcuts | Manifest `share_target` / `shortcuts`: Android Chrome only | Android only |
| Live Activities, Dynamic Island, Android Live Updates, widgets | No web API | **Native only** |
| Quick Look / AVKit media, native diff and terminal renderers | Web equivalents exist but don't feel native | Native-quality only |
| Store presence | Play Store via TWA (cheap); App Store needs a wrapper (Capacitor) and risks guideline 4.2 | Android cheap, iOS costly |

Bottom line: the high-value gaps (push deep link, Back, iOS long-press, swipe actions, sticky modifiers, photo downscale) are all achievable in `packages/ui` and `apps/web` without going native. A native shell is only justified for Live Activities, Live Updates and widgets, and T3 needs a hosted relay to drive even those.
