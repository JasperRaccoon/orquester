# File-Browser Rename Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rename files/folders in the file-browser tab via the right-click context menu or double-clicking the name, with VS Code-style inline editing and a 409 conflict flow that keeps the editor open.

**Architecture:** A new daemon route `POST /api/fs/rename` (sibling of `/api/fs/create`: same fsRoot sandbox + error mapping, plus a `409 FS_EXISTS` conflict answer), a `FsRenameRequest` wire type + client methods in `@orquester/api` and the UI `ApiClient`, and inline-rename state in `FileBrowser.tsx` that prefix-rewrites local tree state on success (mirroring the delete cleanup).

**Tech Stack:** TypeScript 5.8 ESM, Fastify 4 (daemon), React 18 + zustand (UI), lucide-react icons.

Spec: `docs/superpowers/specs/2026-07-25-fs-rename-design.md`.

## Global Constraints

- **⛔ Never launch, restart, or stop the daemon from this checkout** (AGENTS.md): no `pnpm dev*`, no `cli.ts`, no port/socket binds, no `systemctl`. A live daemon is already serving this workspace.
- **No test runner exists in this repo.** The verification gate is `pnpm check` (typecheck, run from the repo root) plus driving the real app — which here means handing manual verification to the user (see Task 4).
- ESM everywhere; packages import each other's TS source directly (no build step between packages).
- When committing, commit to the **current branch as-is** (even `main`) — never create a branch.
- Error-body convention: `{ code, message }`; sandbox violations map `FsSandboxError` → `403 FS_FORBIDDEN`; generic failures → `400 FS_ERROR`.

```ts
  // Rename a file or directory in place (same parent dir — not a move). Sibling
  // of /api/fs/create: same fsRoot sandbox + error mapping. A name conflict is a
  // 409 FS_EXISTS (not FS_ERROR) so the client keeps its inline editor open. A
  // case-only rename on a case-insensitive FS (macOS desktop) sees "itself" at
  // the destination — same dev+ino — and is allowed through. Sessions running
  // inside a renamed dir are left alone: their cwd follows the inode.
  app.post("/api/fs/rename", async (request, reply): Promise<{ ok: true } | void> => {
    const body = (request.body ?? {}) as Partial<FsRenameRequest>;
    const newName = body.newName?.trim();
    if (!body.path || !newName) {
      return reply.code(400).send({ code: "INVALID_REQUEST", message: "path and newName required." });
    }
    if (/[\\/]/.test(newName) || newName === "." || newName === "..") {
      return reply
        .code(400)
        .send({ code: "INVALID_REQUEST", message: "newName must be a plain file or folder name." });
    }
    try {
      const source = await assertInsideFsRoot(resolved.fsRoot, body.path);
      const realRoot = await realpath(resolved.fsRoot).catch(() => resolve(resolved.fsRoot));
      if (source === realRoot) {
        return reply.code(400).send({ code: "FS_ERROR", message: "Cannot rename the workspaces root." });
      }
      if (newName === basename(source)) {
        return { ok: true }; // no-op rename
      }
      const target = await assertInsideFsRoot(resolved.fsRoot, join(dirname(source), newName));
      const sourceStat = await lstat(source); // ENOENT → FS_ERROR below
      const existing = await lstat(target).catch(() => null);
      if (existing && !(existing.dev === sourceStat.dev && existing.ino === sourceStat.ino)) {
        return reply
          .code(409)
          .send({ code: "FS_EXISTS", message: `A file or folder named "${newName}" already exists.` });
      }
      await rename(source, target);
      return { ok: true };
    } catch (error) {
      if (error instanceof FsSandboxError) {
        return reply.code(403).send({ code: "FS_FORBIDDEN", message: error.message });
      }
      return reply.code(400).send({
        code: "FS_ERROR",
        message: error instanceof Error ? error.message : "Cannot rename entry."
      });
    }
  });
```

- [ ] **Step 3: Handlers**

After `confirmDelete` (~line 332), add:

```ts
  const startRename = (target: MenuTarget) => {
    setRenameError(null);
    setRenaming(target);
  };

  const cancelRename = () => {
    setRenaming(null);
    setRenameError(null);
  };

  const submitRename = async (target: MenuTarget, rawName: string) => {
    const newName = rawName.trim();
    if (!newName || newName === target.name) {
      cancelRename();
      return;
    }
    setError(null);
    try {
      await api.renameFsEntry(target.path, newName);
    } catch (e) {
      if (e instanceof ApiError && e.status === 409) {
        // Name conflict: keep the editor open so the user can pick another name.
        setRenameError(e.serverMessage ?? "A file or folder with that name already exists.");
      } else {
        cancelRename();
        setError("Could not rename.");
      }
      return;
    }
    const oldPath = target.path;
    const newPath = joinPath(parentOf(oldPath), newName);
    const rewrite = (p: string) =>
      p === oldPath ? newPath : p.startsWith(oldPath + "/") ? newPath + p.slice(oldPath.length) : p;
    cancelRename();
    setExpanded((prev) => {
      const next = new Set<string>();
      prev.forEach((d) => next.add(rewrite(d)));
      return next;
    });
    // Rewrite cache keys AND entry paths so an expanded subtree keeps rendering
    // (and the live poll re-fetches live paths) until the reload below lands.
    setChildrenByPath((prev) => {
      const next: Record<string, FsEntry[]> = {};
      for (const [d, entries] of Object.entries(prev)) {
        next[rewrite(d)] = entries.map((en) =>
          en.path === oldPath ? { ...en, path: newPath, name: newName } : { ...en, path: rewrite(en.path) }
        );
      }
      return next;
    });
    setSelectedFile((prev) => (prev ? rewrite(prev) : prev));
    setActiveDir((prev) => rewrite(prev));
    await loadDir(parentOf(oldPath));
  };
```

```tsx
/** Inline editor shown in place of a tree row's name while renaming. */
const RenameInput: React.FC<{
  initial: string;
  onSubmit: (value: string) => void;
  onCancel: () => void;
}> = ({ initial, onSubmit, onCancel }) => {
  const [value, setValue] = useState(initial);
  return (
    <Input
      autoFocus
      value={value}
      // 16px on mobile (text-base) prevents iOS from zooming on focus.
      className="h-6 flex-1 px-1.5 text-base md:text-sm"
      onFocus={(e) => e.currentTarget.select()}
      onChange={(e) => setValue(e.target.value)}
      onClick={(e) => e.stopPropagation()}
      onDoubleClick={(e) => e.stopPropagation()}
      // Clicking elsewhere cancels. After a 409 the input keeps focus (Enter
      // doesn't blur), so the conflict flow never hits this.
      onBlur={onCancel}
      onKeyDown={(e) => {
        if (e.key === "Enter") {
          e.preventDefault();
          onSubmit(value);
        } else if (e.key === "Escape") {
          e.preventDefault();
          onCancel();
        }
      }}
    />
  );
};
```

**Do NOT start a daemon from this checkout.** Report completion and give the user this checklist to run in their live instance (after their usual deploy/restart):

1. Right-click a file → Rename → new name + Enter → row updates, no reload needed.
2. Double-click a folder's name → inline input appears with the name pre-selected; Escape restores it; clicking elsewhere cancels.
3. Rename to an existing sibling's name → red "already exists" message under the input, input still open; correcting the name then succeeds.
4. Rename an expanded folder containing the currently open file → tree stays expanded, the open file stays open under its new path.
5. Rename with `/` in the name → generic "Could not rename." (server 400).
6. On mobile/touch: long-press → Rename works.
